# Модель-заменитель и оптимизация (`surrogate.py`)

Узел платформы трека «Простая литая ГТУ-заменитель». Дорогой расчёт (SU2 — ступени,
OpenFOAM — горение и теплообмен, CalculiX — прочность) даёт таблицу «параметры → показатели».
Модуль строит по ней модель-заменитель, ищет оптимум только там, где есть данные, и выбирает
следующую порцию точек для дорасчёта.

| шаг | что делает | чем |
|---|---|---|
| план | точки в заданных границах | `scipy.stats.qmc`: Соболь (скремблированный) или латинский гиперкуб (`random-cd`) |
| модель | параметры → показатели, со средним и СКО | ансамбль MLP (`sklearn.neural_network.MLPRegressor`, lbfgs) и гауссовский процесс (`GaussianProcessRegressor`) как базовая линия |
| проверка | ошибка по каждому показателю | перекрёстная по блокам (`GroupKFold`) и отложенная выборка |
| оптимум | максимум/минимум показателя при ограничениях | `scipy.optimize.differential_evolution` в прямоугольнике данных, штрафы за край и дыры, флаг неопределённости |
| дорасчёт | следующая порция из k точек | ожидаемое улучшение × вероятность выполнить ограничения, порция — Kriging believer |

## Установка

```bash
pip install scikit-learn scipy numpy        # joblib и threadpoolctl ставятся вместе со scikit-learn
pip install cantera pytest                  # только для теста: заменитель берётся из gtu_explore.comp_stage
```

Проверено: Python 3.13.18, scikit-learn 1.9.1, scipy 1.18.1, numpy 2.5.3, cantera 3.2.0,
pytest 9.2.0 (Linux, 4 ядра). AWS модулю не нужен: модель учится и считает локально за секунды,
на AWS идут только дорогие расчёты точек плана.

## Команды

```bash
python surrogate.py plan --problem problem.json --n 64 --method sobol --out plan.csv
#   ... дорогие расчёты точек plan.csv -> runs.csv (входы + показатели) ...
python surrogate.py fit --problem problem.json --data runs.csv --holdout hold.csv \
       --blocks kmeans --log D2 --out model.joblib --report report.json
python surrogate.py optimize --model model.joblib --objective eta --max \
       --constraint "PR>=4.25" --constraint "D2<=0.40" --fixed T1=288.15 --out opt.json
python surrogate.py next --model model.joblib --objective eta --k 8 \
       --constraint "PR>=4.25" --fixed T1=288.15 --out next.csv
python -m pytest -q -s test_surrogate.py    # тест, 2–5 мин на 4 ядрах (или python test_surrogate.py)
```

Все четыре команды прогнаны в этой сессии на данных заменителя (128 точек Соболя, отложенные
64 случайные точки); `fit` (перекрёстная по блокам + обучение MLP и GP) на 128 точках — 73 с на машине, занятой соседними расчётами.
Повтор при независимой проверке (те же объёмы, `--blocks batch` по 16 строк, `--log D2`, `--jobs 4`):
157 с при средней загрузке 12–16 на 4 ядрах; оптимум PR ≥ 4,25, D2 ≤ 0,40 по MLP и по GP — прямой
eta 0,8582 и 0,8583 (истинный 0,8583), флагов нет.

Ключи `fit`: `--kinds mlp,gp` (первая — основная), `--folds 5`, `--blocks kmeans | order | <столбец>`,
`--n-blocks 20`, `--members 8`, `--hidden 32,32`, `--alpha auto | число`, `--log` (показатели,
которые учить в логарифме), `--jobs 4`. `optimize`: `--kind mlp|gp`, `--kappa 1`, `--edge 0.05`,
`--tol`, `--min`. `next`: `--kind gp|mlp`, `--k`, `--domain bounds|studied`.

## Данные

- `problem.json`: `{"inputs": {"U2": [350, 650], "m": [1.5, 25], "T1": [243.15, 318.15]}, "outputs": ["eta", "PR", "D2"]}`.
- `plan.csv` — столбцы входов. `next.csv` — столбцы входов и `mode` (`ei` | `ucb` | `pof` — по чему
  выбрана точка), `acq` (значение этого критерия: EI × PoF, μ + 2σ или PoF — единицы разные), `ei`
  (EI × PoF в единицах цели при любом режиме; по нему, а не по `acq`, судят, исчерпан ли дорасчёт),
  `pof`, `pred_<цель>`, `sd_<цель>`.
- `runs.csv` — заголовок + столбцы входов и показателей; лишние столбцы допускаются (например,
  номер порции для `--blocks <столбец>`). Строка с пустым или нечисловым показателем —
  неудачный прогон: отбрасывается и считается (`dropped` в отчёте), а не подменяется.
- `model.joblib` — модель вместе с обучающими данными и отчётом проверки (`joblib`, тот же
  scikit-learn при загрузке). Классы в нём — `surrogate.*` и при запуске `python surrogate.py fit`,
  поэтому модель грузится и командами `optimize`/`next`, и из Python (`import surrogate;
  surrogate.Surrogate.load(...)`, папка модуля — в `sys.path`). `report.json` — ошибки перекрёстной
  проверки и отложенной выборки.

## Как устроено

**План.** Соболь даёт равномерность при n = 2^k; при другом n берутся первые n точек из 2^k
и выдаётся предупреждение. Латинский гиперкуб — ровно одна точка в каждой из n полос по
каждой оси. В выводе — центрированная L2-неравномерность (`discrepancy_cd`).

**Модели.** Входы приводятся к [0, 1] по границам задачи, показатели стандартизуются.
- MLP: ансамбль из 8 сетей (tanh, 32×32, lbfgs), у каждой своя инициализация и бутстреп-выборка;
  по умолчанию своя сеть на каждый показатель. L2-регуляризация `alpha` подбирается по каждому
  показателю внутренней 4-кратной проверкой из {1e-4, 1e-3, 1e-2, 0,1, 1}: у шумного КПД
  выбирается 0,1, у гладких PR и D2 — 1e-4. СКО прогноза — разброс членов ансамбля.
- GP: по процессу на показатель, ядро Matérn ν = 2,5 с отдельной длиной по каждой оси +
  белый шум; гиперпараметры — максимум правдоподобия, 3 перезапуска. Прогноз даёт СКО самой
  функции (без шума) и оценку шума расчёта.
- `log` — показатель учится в логарифме (положительные величины с разбросом в разы: диаметр,
  расход, напряжение).
- BLAS ограничен одним потоком (`SURROGATE_BLAS_THREADS`): матрицы малы, а при занятой машине
  многопоточный BLAS тормозит. Замер при средней загрузке около 6 на 4 ядрах: обучение GP
  (200 точек, 3 показателя) 18,5 с → 4,9 с, одна сеть MLP 3,6 с → 0,25 с.

**Проверка.** `block_cv`: точки делятся на блоки — пространственные кластеры k-средних
(по умолчанию 20; из обучения выпадает целый район, оценка честнее случайного деления) или
подряд идущие порции прогонов (`order`, либо столбец с номером порции); блоки — на 5 частей.
`validate` — отложенная выборка. По каждому показателю: RMSE, MAE, максимум модуля ошибки,
MAPE, 95-й процентиль и максимум относительной ошибки (%), R², доля точек с |ошибкой| ≤ 2 СКО
(`cover_2sd`). СКО GP в проверке включает оценку шума расчёта, СКО MLP — только разброс ансамбля,
без шума; поэтому к зашумлённым данным `cover_2sd` у MLP заведомо ниже 0,95 (в тесте 0,39 против
0,89 у GP) и калибровку неопределённости судят по GP.

**Оптимум.** Поиск — только в прямоугольнике обучающих данных, не в номинальных границах.
Минимизируется
`−(μ − κσ)/s + w_con·Σ нарушений + w_edge·Σ(1 − d/edge)² + w_gap·(r − 2)²₊`:
осторожная оценка цели (κ = 1; ограничения тоже осторожные, μ ∓ κσ), штраф в полосе 5 %
у края изученной области по свободным осям, штраф, если ближайшая обучающая точка дальше
двух типичных расстояний между соседями (медиана расстояний до ближайшего соседа по различным
точкам: повторы одной точки её не обнуляют). Штраф за край действует только у краёв прямоугольника
данных; ограничение по входу (`U2<=620`) — обычное ограничение, без полосы. Закреплённые входы (`fixed`, например T1 = ISO)
должны лежать внутри изученной области. Флаги в ответе: `sigma` — СКО основной модели в
оптимуме больше допуска; `disagree` — MLP и GP расходятся больше допуска; `gap` — дыра в
данных; `constraint` — ограничения не выполнены по среднему прогнозу. Отдельно `at_edge` —
оси, по которым без штрафа за край модель ушла бы дальше: оптимум упирается в край, истинный
может лежать снаружи, план надо расширять. Допуск — `--tol`; без него 2 RMSE перекрёстной
проверки из `fit`, иначе 0,1 СКО цели по данным.

**Дорасчёт.** Кандидаты — 3072 точки Соболя в номинальных границах + 1024 вокруг текущего
лучшего прогноза. Критерий — ожидаемое улучшение (EI) над лучшим средним прогнозом среди
кандидатов, выполняющих ограничения (так шум отдельных расчётов не становится «рекордом»),
умноженное на вероятность выполнить ограничения. Порция: выбранная точка добавляется в GP
как точная (Kriging believer, гиперпараметры прежние), EI пересчитывается; кандидаты ближе
половины типичного расстояния к уже выбранным исключаются. Когда EI исчезает везде (меньше
1e-6 СКО цели), точка берётся по μ + 2σ среди кандидатов с вероятностью ограничений ≥ 0,5
(режим `ucb` в выводе).

## Проверка на заменителе дорогого расчёта (`test_surrogate.py`)

Заменитель — центробежная ступень `gtu_explore.comp_stage` (титановое колесо), обращённая по
окружной скорости: входы U2 = 350…650 м/с, m = 1,5…25 кг/с, T1 = 243…318 K → КПД eta,
степень сжатия PR (подбирается `brentq` так, чтобы `comp_stage` дала заданную U2), диаметр
колеса D2. Шум: eta + N(0; 0,003), PR × (1 + N(0; 0,005)), D2 без шума. Обучение — 200 точек
латинского гиперкуба, отложенная выборка — 256 точек Соболя с другим зерном. Истинные значения:
eta 0,807…0,881, PR 2,13…9,18, D2 0,167…0,859 м.

Критерий — не более 1 п. п. и между моделью и прямым расчётом, и между прямым расчётом в

Флагов неопределённости нет. По m оптимум не единствен: в модели `comp_stage` зазор
cl = 0,0007·D2 при D2 ≥ 0,43 м, и КПД от m не зависит, поэтому точки сравниваются по КПД.

Только изученная область: модель обучена на 86 точках с U2 ≥ 521 м/с, истинный оптимум случая
PR ≥ 4,25 лежит снаружи (U2 = 505,5). Найдено U2 = 527,3 (внутри данных), прямой eta 0,8544

СКО GP по eta вне данных (U2 = 400) — 0,0094, внутри — 0,0006. При заведомо малом допуске
выставляется флаг `sigma`; закрепить вход вне изученной области нельзя (ошибка).

Дорасчёт: порция из 8 точек (3 по EI, 5 по μ + 2σ) легла у границы ограничения:
медиана |PR − 4,25| = 0,024 против 1,68 у 8 случайных точек; точки не повторяются (минимальное
расстояние не меньше половины типичного). После добавления порции оптимум по GP: прямой eta
0,8585 (было 0,8583), прогноз модели 0,8589.

`test_09_robustness` — дефекты, найденные независимой проверкой: модель из `python surrogate.py fit`
(отдельный процесс) грузится через `import surrogate`; `next.csv` несёт столбцы `mode` и `ei`;
на данных, где каждая точка посчитана дважды, типичное расстояние то же, что без повторов
(0,149), и оптимум аналитической функции −(x − 0,3)² − (y − 0,6)² найден в (0,301; 0,601) — до
исправления медиана расстояний была 0, и оптимум приковывался к обучающей точке (0,838; 0,323)
без флагов; ошибки имён в `propose` — понятные.

Повтор теста в чистой папке (копия `gtu_explore.py`, `surrogate.py`, `test_surrogate.py`, без
кэшей) — 8 тестов пройдены, все числа совпали с исходным прогоном. Другие зёрна плана и шума
(200 точек латинского гиперкуба, зёрна 1–4; отложенная выборка — те же 256 точек Соболя):

| проверка | MLP | GP | критерий |
|---|---|---|---|
| отложенная выборка, eta, максимум относительной ошибки к истине | 0,36…0,54 % | 0,31…0,55 % | ≤ 2 % |
| то же, RMSE eta к истине | 0,095…0,112 п. п. | 0,083…0,110 п. п. | < 0,3 п. п. |
| оценка шума eta по GP | — | 0,00257…0,00318 | 0,003 ± 35 % |
| случаи A, B, C: прогноз в оптимуме − прямой расчёт | ≤ 0,091 п. п. | ≤ 0,100 п. п. | ≤ 1 п. п. |
| то же: прямой в найденной точке хуже истинного оптимума | ≤ 0,020 п. п. | ≤ 0,027 п. п. | ≤ 1 п. п. |

Флагов и `at_edge` ни в одном из 24 случаев нет; PR в случае C — 6,488…6,520 при пороге 6,5
(нарушение не больше 0,18 %, в допуске 1 %). Два новых случая при T1 = 288,15 K, зёрна 2–4:

- D — максимум PR при D2 ≤ 0,45 м и U2 ≤ 600 м/с: найдено U2 = 600,0 (ограничение по входу
  выходит на границу без полосы штрафа), прямой PR 6,2891 = истинному оптимуму 6,2891; прогноз
  модели 6,276…6,301.
- E — минимум D2 при eta ≥ 0,855, PR ≥ 4,0, m = 10 кг/с: прямой D2 0,4292…0,4308 м против
  0,4281 м у истинного оптимума (на 0,3…0,6 % больше), прямой eta 0,8556…0,8563 — ограничение
  выполнено строго: осторожная оценка μ − σ отодвигает точку от границы по зашумлённому КПД.

Сверено с исходниками установленных версий (scipy 1.18.1, scikit-learn 1.9.1): равномерность
Соболя только при n = 2^k (`_qmc.py`), `LatinHypercube(optimization="random-cd")`, `discrepancy` по
умолчанию `method="CD"`; СКО `GaussianProcessRegressor.predict` включает `WhiteKernel`
(`WhiteKernel.diag` = noise_level), поэтому вычитание шума в `GPModel.predict` верно;
`differential_evolution(vectorized=True)` передаёт x формы (N, S) и при `init="sobol"` берёт
население — ближайшую сверху степень двойки; `GroupKFold` по умолчанию без перемешивания;
`MLPRegressor.alpha` — L2-регуляризация. Формула EI `expected_improvement` совпадает с
реализацией BoTorch (`botorch/acquisition/analytic.py`: σ·(φ(u) + u·Φ(u)), u = (μ − f*)/σ) и с
Монте-Карло E[max(f − f*, 0)] (2·10⁶ выборок, расхождение < 0,2 %); статья Jones, Schonlau,
Welch 1998 при проверке не открывалась.

## Ограничения и что не проверено

- Критерий «2 % по КПД» на этом заменителе слабый: eta меняется лишь в 0,807…0,881, и 2 %
  (около 1,7 п. п.) — четверть всего размаха. Поэтому добавлены строже: максимум по 256
  точкам (а не среднее) и RMSE меньше СКО шума одного расчёта.
- Заменитель гладкий и трёхмерный. На реальных данных SU2/OpenFOAM/CalculiX модуль не
  проверялся — их ещё нет; при 5–10 входах 200 точек может не хватить — это покажет
  перекрёстная по блокам.
- `comp_stage` — одномерная оценка с принятыми коэффициентами (см. README трека); тест
  проверяет машинерию модели и оптимизации, а не физику ступени.
- GP — O(n³) по времени, O(n²) по памяти; обучение проверено до 208 точек, больше не пробовалось.
- Связка с `platform/aws/runner.py` не сделана: формат задач раннера с этим узлом не
  согласован; обмен — через `plan.csv` / `next.csv` и `runs.csv`.
- Времена замерены на машине, где параллельно шли другие расчёты (средняя загрузка 2–16 на 4 ядрах).
