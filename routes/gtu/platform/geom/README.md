# Геометрия и сетка колеса компрессора (`impeller.py`)

Узел платформы трека «Простая литая ГТУ-заменитель»: параметрическое центробежное колесо
по данным одномерного расчёта → твёрдотельная модель (STEP) и расчётная область одного
межлопаточного канала с периодическими гранями → тетраэдрическая сетка в формате SU2.
Ядро геометрии — Gmsh 4.15.2 с Open CASCADE.

## Команды

```bash
pip install gmsh numpy scipy cantera pytest   # cantera нужна gtu_explore.py (свойства газа, comp_stage)
apt-get install -y libglu1-mesa                # колесу gmsh из pip нужна libGLU.so.1, иначе import gmsh падает

python impeller.py --case core130 --level coarse            # схема 130 gtu_explore
python impeller.py --case taurus60 --level coarse           # пакет Taurus 60, одно колесо
python impeller.py --case custom --m 10 --pr 4.5 --rpm 22000 --d2 0.44 --level medium
python impeller.py --case core130 --z 8 --beta2b 40 --gap 0.4e-3 --no-step   # переопределить параметры
python impeller.py --case core130 --level coarse --record   # дописать итог в impeller_results.json
python -m pytest -q -s test_impeller.py                     # тесты: 23 проходят + 2 пропуска, 4–5,5 мин на 4 ядрах
```

Прочие ключи: `--no-splitters`, `--m-split`, `--incidence`, `--no-mesh`, `--msh` (ещё и `.msh`),
`--threads`, `--out`, `--verbose`. Уровни сетки: `coarse`, `medium`, `fine`. Недопустимые исходные данные
(m ≤ 0, PR ≤ 1, D2 или частота ≤ 0, Z < 3, зазор < 0, `m_split` вне (0; 1), beta2b вне [0; 70) град) —
отказ `ValueError` до построения. Зазор 0 допустим (лопатка касается покрышки, грани вершины нет).
`--record` с переопределёнными параметрами пишет запись с суффиксом `_mod_<параметры>`, опорную не затирает.

Результаты пишутся в `out/<case>_<level>/` (папка в `.gitignore`, файлы десятки МБ):

| файл | что это |
|---|---|
| `impeller_<case>.step` | колесо: втулка с задним диском + Z основных лопаток + Z полулопаток, одно тело |
| `passage_<case>.step` | расчётная область одного канала (основная лопатка + полулопатка) |
| `passage_<case>_<level>.su2` | сетка, ASCII; объём `fluid`, маркеры `inlet outlet hub shroud blade periodic_1 periodic_2` |
| `impeller_<case>_<level>.json` | все параметры, одномерная увязка, диагностика, статистика сетки, время |

`impeller_results.json` в этой папке — краткие итоги прогонов (`--record`), без больших файлов.

## Исходные данные случаев

Числа берутся из results-JSON трека, а не вписываются руками:

- `core130` — `gtu_explore_results.json`, схема 130: расход 39,8 кг/с на 4 ядра → 9,95 кг/с на колесо,
  PR 4,25, 22 197 об/мин, D2 0,435 м (U2 506 м/с; в `gtu_explore` колесо этой схемы алюминиевое).
- `taurus60` — `gtu_dropin_results.json`, одно колесо (1Ц), охлаждаемый сопловой аппарат (N): 22,5 кг/с,
  PR 6,75; D2 и частота — `gtu_explore.comp_stage`: 0,591 м, 19 951 об/мин, U2 618 м/с
  (в JSON округлённо 0,59 м и 19 967 об/мин — там расход до округления).
- `custom` — задаются `--m --pr` и при желании `--rpm --d2`; недостающее даёт `comp_stage`.

## Одномерная увязка (что считается и откуда)

| величина | как получена |
|---|---|
| D2, частота, работа w, T2, КПД | `gtu_explore.comp_stage` (коэффициент работы psi = w/U2² = 0,70; если D2 и частота заданы, psi пересчитывается); пределы U2 и T2 — `gtu_explore.LIM` по материалу колеса (Ti 620 м/с; Al 520 м/с и T2 ≤ 473 К), превышение — предупреждение |
| ширина на выходе b2, зазор | формулы `comp_stage`: Cm2 = 0,28 U2, плотность rho1·PR^0,62/(…), зазор max(0,3 мм; 0,0007 D2) |
| D1s | минимум относительной скорости на периферии входа при D1h/D1s = 0,35, без закрутки; статика входа по таблицам Cantera из `gtu_explore` |
| углы входа beta1h, beta1s | треугольник скоростей при осевом входе + угол атаки (по умолчанию 0) |
| загиб назад beta2b | под psi по формуле проскальзывания Визнера sigma = 1 − √cos beta2b / Z^0,7, Z — все лопатки на выходе (основные + полулопатки). У Визнера sigma = 1 − Cслип/U2, поэтому при входе без закрутки psi = Ctheta2/U2 = sigma − 0,28 tg beta2b (до проверки 14.11.2026 в коде стояло sigma (1 − 0,28 tg beta2b) — смешение с определением Стодолы Ctheta2/Ctheta2∞, загиб получался на 3,8 град больше). Паразитная работа (трение диска, перетечки) не выделена: psi = w/U2² приравнивается эйлеровой. Предел применимости формулы eps_lim = exp(−8,16 cos beta2b / Z) сравнивается с D1s/D2, выше — предупреждение |
| осевая длина Lz | корреляция Lz = D2 (0,014 + 0,023 D2/D1h + 1,58 phi), phi = m/(rho01 π r2² U2), приписываемая Аунгиру (2000); взята по вторичным источникам, с книгой не сверена |

## Геометрия (параметры и допущения)

- **Меридиональный контур.** Втулка и покрышка — кубические кривые Безье от входной кромки (z = 0,
  касательная осевая) до выхода (r = r2, касательная радиальная): втулка (0, r1h) → (Lz, r2),
  покрышка (0, r1s) → (Lz − b2, r2). Внутренние точки — доли осевой длины и радиального подъёма
  (`hub_bz`, `sh_bz`, по умолчанию 0,5/0,5). Отношение площадей выход/вход 0,63 (core130), 0,48 (taurus60).
- **Лопатка — линейчатая** (как под фланкирование): средняя поверхность из отрезков, соединяющих точки
  втулки и покрышки при равной доле меридиональной длины m. Входная кромка радиальная (theta = 0 на
  втулке и покрышке).
- **Закон углов.** beta(m) = beta_вх + (beta2b − beta_вх)·F(m), F — кубический Безье (0, c1, c2, 1),
  по умолчанию c1 = 0, c2 = 1 (нулевая производная на обеих кромках). Угол охвата
  theta = −∫ tg beta / r dm. Чтобы выходная кромка была осевой (без наклона, `rake` = 0), к закону
  втулки добавляется горб Δ·sin²(πm), Δ находится численно (−20,7 град для core130, −22,6 для
  taurus60; угол на втулке в середине канала опускается до 11,1 и 10,4 град).
- **Толщина** линейно по размаху: у втулки 0,011 D2, у периферии 0,0045 D2 (4,8/2,0 мм для D2 0,435 м);
  у входной кромки утонение до 0,4 толщины на 8 % длины, у выходной — до 0,7 на 5 %. Толщина
  откладывается по нормали к средней поверхности в середине размаха сечения; кромки срезанные
  (плоский торец входной, цилиндрический r = r2 выходной). Скругления кромок и галтели у втулки
  не строятся. Прочность этих толщин не проверялась — дело узла CalculiX.
- **Лопатки.** По умолчанию 9 основных + 9 полулопаток; полулопатка — та же средняя поверхность,
  повёрнутая на 360/(2Z) и начатая с m = 0,30. Число лопаток — принятое значение (`--z`).
- **Радиальный зазор.** Вершина лопатки обрезается телом вращения, ограниченным кривой покрышки,
  смещённой внутрь на зазор; зазор в области заполнен жидкостью. По узлам сетки зазор
  0,3045 мм (core130) при заданном 0,3045 мм.
- **Твёрдое тело.** Втулка — тело вращения: носок длиной 0,3 r1h, задний диск толщиной
  max(0,03 D2; 1,5·0,25 b2), центральное отверстие 0,35 r1h; лопатки заходят в неё на 0,25 b2 и
  сплавляются. Масса — по объёму: core130 6,16 дм³ (27,3 кг из Ti-6Al-4V при 4430 кг/м³; 17,0 кг из
  алюминиевого сплава 2618 при 2760 кг/м³), taurus60 15,63 дм³ (69,2 кг Ti-6Al-4V). Облегчений диска
  нет, масса завышена. Объём считается по частям: втулка + Z·(лопатки − их часть внутри втулки);
  `getMass` OCC для сплавленного тела давал на 0,55 % больше (ошибка интегрирования по грани втулки
  с 18 вырезами; повторено при проверке: 6,2029 против 6,1684 дм³ — до исправления загиба), по частям — совпадает
  (тесты 2 и 3) с формулой Паппа-Гульдина для втулки, с объёмом
  тетраэдрической сетки и с объёмом STEP, прочитанного обратно.

## Расчётная область и сетка

- Область: входной участок длиной 1,0 r1s (с z = −r1s), колесо, безлопаточный участок до 1,3 r2.
- Периодические поверхности — средняя поверхность лопатки, повёрнутая на −360/(4Z) (между основной
  лопаткой и полулопаткой соседнего канала), и её копия, повёрнутая на +360/Z. Во входном участке
  поверхность продолжена винтом с затухающим шагом, за колесом — логарифмической спиралью с углом
  beta2b. `periodic_2` = поворот `periodic_1` на +360/Z вокруг +z.
- Построение: тело вращения проточной части на секторе → `fragment` двумя периодическими
  поверхностями → средний объём → вычитание обрезанных лопаток. Угловой охват сектора считается по
  первой поверхности плюс шаг 360/Z (до проверки 14.11.2026 — развёрткой общего списка точек обеих
  поверхностей; при Z = 3 скачок между ними > 180 град ломал развёртку, и построение падало с «нет граней
  для маркеров ['blade']»). Средний объём проверяется: ровно 3 объёма, один касается обеих поверхностей,
  и его объём равен 1/Z тела вращения (допуск 1·10⁻³ — точность `getMass` OCC: на прогонах отклонение
  от 2·10⁻⁵ до 2·10⁻⁴; при ошибке выбора объёма — десятки процентов; отклонение пишется в JSON). Маркеры назначаются по геометрии:
  точки рёбер каждой грани проверяются на плоскость входа, цилиндр выхода, контуры втулки и
  покрышки, периодические поверхности; остальное — лопатка.
- Сетка: тетраэдры, 2D Frontal-Delaunay, 3D HXT, оптимизация Gmsh. Размеры задаются полями:
  у лопаток h_b, в канале h0, по высоте зазора h_зазор (в трубке вокруг рёбер вершины лопатки),
  у кромок — по толщине кромки.

| уровень | h0 | h_b | ячеек по зазору |
|---|---|---|---|
| coarse | b2/3 | b2/7 | 1 |
| medium | b2/5 | b2/12 | 2 |
| fine | b2/8 | b2/20 | 3 |

- Периодичность сетки: Gmsh копирует сетку `periodic_1` на `periodic_2` поворотом, но проецирует узлы
  на ведомую грань, обрезанную отдельно, — расхождение до 1·10⁻⁸ м (порядок допуска OCC). Перед
  записью узлы ведомой грани ставятся точно в повёрнутые узлы ведущей; величина поправки
  пишется в JSON (`mesh.periodic_snap`).

## Тесты (`test_impeller.py`)

Строит оба случая через CLI (`--level coarse`) во временную папку и проверяет записанные файлы
независимо от Gmsh (файл SU2 разбирается заново, numpy):

1. одномерные данные: D2, частота, PR случая; U2 ≤ 620 м/с; зазор по формуле `comp_stage`; psi сходится;
   независимо от кода: sigma Визнера по записанному beta2b даёт sigma − phi2 tg beta2b = psi;
2. объём втулки (OCC) = объёму по теореме Паппа-Гульдина по меридиональному контуру (до 1·10⁻⁶);
3. STEP читается обратно одним телом, его объём совпадает с объёмом, посчитанным при построении
   (до 1·10⁻⁴) и с объёмом его тетраэдрической сетки (до 2·10⁻³), наибольший радиус поверхности = r2;
4. в SU2 ровно 7 маркеров с нужными именами, все непустые, только треугольники;
5. только тетраэдры, объём каждой ячейки > 0, мера формы 12(3V)^(2/3)/Σl² > 0, minSICN Gmsh > 0;
   сумма объёмов ячеек = объёму области OCC (до 5·10⁻³); канал до вычитания лопаток = 1/Z тела вращения;
6. граница замкнута и размечена полностью: грани, принадлежащие одной ячейке, = объединению
   треугольников маркеров, ни один треугольник не входит в два маркера;
7. узлы `periodic_1`, повёрнутые на 360/Z, совпадают с узлами `periodic_2` (≤ 1·10⁻¹⁰ D2),
   отображение взаимно однозначно, треугольники совпадают; поправка узлов при записи < 1·10⁻⁶ D2;
8. узлы маркеров лежат на своих поверхностях: inlet — на плоскости входа, outlet — на цилиндре
   выхода, hub/shroud — на своих контурах (≤ 1·10⁻⁵ D2), лопатка — внутри r1h…r2, не во входном
   участке (z > −половины толщины) и на расстоянии зазора от покрышки.

Классы: `TestCore130`, `TestTaurus60` (оба с STEP колеса), `TestFewBlades` (граничный Z = 3, без STEP колеса:
проверки 1, 4–8), `TestInputs` (отказ на недопустимых данных, без Gmsh).

## Что не сделано и не проверено

- SU2 в этом контейнере не установлен: файл не читался `SU2_CFD`. Формат проверен своим разбором
  (выше) и соответствует писателю SU2 в Gmsh; конфигурацию SU2 (MARKER_PERIODIC, вращающаяся
  система отсчёта, неподвижная покрышка как стенка, вращающаяся в обратную сторону в
  относительной системе) должен задать узел SU2. Для неё в JSON записаны ось, угол 360/Z и
  угловая скорость (`su2`).
- Пристенных призматических слоёв нет — для RANS с y+ ≈ 1 сетку нужно дополнять.
- Маркер `hub` один на всю стенку втулки: вращающийся носок и колесо и неподвижная стенка безлопаточного
  диффузора (z = Lz, r2 < r ≤ 1,3 r2). Во вращающейся системе SU2 стенка диффузора тоже будет вращаться;
  набор из 7 маркеров задан заданием узла, разделение не сделано — числа по диффузору с оговоркой.
- Корреляция осевой длины (Аунгир) и формула Визнера (определение sigma через скорость проскальзывания,
  предел eps_lim, какой диаметр входа брать в eps_lim) не сверены с первоисточниками: книга Аунгира и статья
  Визнера (1967) из контейнера недоступны. Определение sigma = 1 − Cслип/U2 согласовано с теорией Буземана:
  при B = 1 (ниже предельного отношения радиусов) скорость проскальзывания не зависит от расхода, как и
  формула Визнера. Толщины, число лопаток, контуры Безье, длины участков области — принятые значения,
  не результат оптимизации.
- Реальных вызовов AWS нет; уровни medium/fine для прогонов на AWS — см. `impeller_results.json`.
