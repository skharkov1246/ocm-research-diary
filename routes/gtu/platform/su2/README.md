# Расчёт ступени в SU2: один канал центробежного колеса

Узел платформы трека «Простая литая ГТУ-заменитель» (issue #59): сетка канала из `../geom/impeller.py` →
SU2 (сжимаемые уравнения Рейнольдса во вращающейся системе) → невязки, расход, полная степень сжатия и
изоэнтропический КПД по полным параметрам. Состояние — в разделе «Проверка»; числа SU2 по колесу пока
**не являются характеристикой** (грубая тетраэдрическая сетка без пристенных призм, см. «Ограничения»).

## Установка SU2

Проверено 14.11.2026 в этом контейнере (Ubuntu 24.04, g++ 13.3, 4 ядра):

- apt Ubuntu 24.04: `apt-cache search --names-only su2` — 0 совпадений; PyPI `https://pypi.org/pypi/su2/json` — 404.
- conda-forge: в индексе `conda-forge/linux-64/current_repodata.json` (скачан здесь, 137 033 пакета) есть
  `su2` **8.5.0** (сборки py310 и py311, зависят от openmpi ≥ 5.0.10 и mpi4py), v8.6.0 там нет; `micromamba`
  2.10.0 там тоже есть, но установщик `micro.mamba.pm` из контейнера — 403. Путь conda не проверялся: нужная
  версия 8.6.0 собрана из исходников (ниже). Готовые архивы выпусков GitHub не проверены: страницы выпусков и
  API GitHub отвечают 403; клон по git работает.
- работает сборка из исходников: `bash install_su2.sh [префикс] [папка исходников]`. Скрипт ставит
  `openmpi-bin libopenmpi-dev` (apt), клонирует тег `v8.6.0`, `./meson.py setup build_mpi -Dwith-mpi=enabled
  -Dbuildtype=release`, `./ninja -C build_mpi install`. Здесь: `apt-get install -y libopenmpi-dev` (OpenMPI
  4.1.6), затем `meson.py setup` + сборка с установкой — 8 мин на 4 ядрах (клон тега v8.6.0 и подмодули уже
  лежали от прежней сборки без MPI), код 0, `ldd SU2_CFD` → `libmpi.so.40`. Версия: `SU2_CFD --help` →
  `SU2 v8.6.0 "Harrier"`. `install_su2.sh` на готовых исходниках и папке сборки (ветка `--reconfigure`,
  новый префикс) — 4 с, код 0, `SU2_CFD --help` из нового префикса отвечает; путь «с нуля» (клон + полная
  сборка) самим скриптом здесь не запускался — шаги те же, что выполнены вручную выше.
- после установки: `export SU2_RUN=<префикс>/bin PATH=<префикс>/bin:$PATH`.
- **Особенность OpenMPI 4.1.6:** MPI-сборка SU2, запущенная одним процессом (без `mpirun` или `-np 1`),
  падает в `MPI_Win_create` («MPI_ERR_WIN: invalid window»); с `OMPI_MCA_osc=pt2pt` идёт, с 4 процессами
  идёт и без него. `run_case.py` ставит эту переменную сам при `--np 1` и в сухом прогоне.
- Под root `mpirun` требует `--allow-run-as-root` — `run_case.py` добавляет сам.

Сборка в этом контейнере лежит в scratchpad сессии и после перезапуска контейнера пропадёт; на AWS и в новой
сессии — заново `install_su2.sh` (~10 мин на 4 ядрах, на c7a.16xlarge быстрее).

## Постановка (шаблон `impeller_passage.cfg.tpl`)

| что | как задано | откуда |
|---|---|---|
| уравнения | `SOLVER= RANS`, `KIND_TURB_MODEL= SST` (по умолчанию V2003m) или `SA` (`--turb SA`) | — |
| газ | идеальный газ, γ = 1,4, R = 287,058, вязкость по Сазерленду | — |
| вращение | `GRID_MOVEMENT= ROTATING_FRAME`, ось z, `ROTATION_RATE` = ω из JSON сетки × доля частоты стадии; скорость в решении абсолютная | `su2.rotation_rate_rad_s` |
| стенки | hub и blade — адиабатные с прилипанием, вращаются с колесом (`MARKER_HEATFLUX`). Покрышка (`--shroud`): `stationary` — с прилипанием, неподвижна (`MARKER_SHROUD`), открытое колесо — по умолчанию; `rotating` — вращается (закрытое колесо); `slip` — без трения (`MARKER_EULER`). Стенки за колесом r ≥ r2 (`--vaneless`): `as-is` — как в сетке (часть hub вращается); `stationary` или `slip` — копия сетки с маркерами `hub_vaneless`, `shroud_vaneless` (`split_vaneless`) | — |
| периодичность | `MARKER_PERIODIC= (periodic_1, periodic_2, центр 0, угол (0, 0, 360/Z), сдвиг 0)` | `su2.periodic` |
| вход | Giles `TOTAL_CONDITIONS_PT`: p01, T01, направление (1, 0, 0) в осях решётки = по нормали, без закрутки | `d1.p01`, `d1.T01` |
| выход | Giles `STATIC_PRESSURE_1D`: статическое давление на r = 1,3 r2 | оценка `estimate_p_out` или `--p-out` |
| турбомашинные маркеры | `MARKER_TURBOMACHINERY= (inlet, outlet)`, `AXIAL_CENTRIFUGAL`, `TURBO_PERF_KIND= COMPRESSOR`, осреднение `MIXEDOUT` | — |
| разгон | `RAMP_MOTION_FRAME` (частота) и `RAMP_OUTLET` (давление на выходе) — линейно, обновление каждые 5 итераций (`--ramp-freq`); давление растёт вдвое дольше частоты и отстаёт от неё | стадии плана |
| начальное поле | M = 0,4 вдоль +z (`AOA= 90`), статические p, T — из p01, T01 при этом M; рампа давления на выходе стартует с этого статического давления | — |
| схема | Roe, первый порядок на разгоне, `MUSCL` + Venkatakrishnan на рабочей точке; неявная схема, CFL 5 с `CFL_ADAPT` (1–20), FGMRES + ILU; `MGLEVEL= 0` (Giles — только на мелкой сетке) | — |
| вывод | `history_<стадия>.csv`: невязки, `Avg_Massflow/TotalPress/TotalTemp(inlet/outlet)` (осреднение по расходу), группа `TURBO_PERF` | — |

Оценка давления на выходе (`estimate_p_out`, граничное условие, а не результат): p02 = PR·p01 из JSON сетки
(ступень), работа ∝ доля частоты², расход ∝ доле частоты; на r = 1,3 r2 закрутка Cθ = ψ·U2·r2/r
(сохранение момента), меридиональная скорость — из неразрывности при ширине b2. Для `core130` на
номинале — 311 кПа. Точку характеристики задаёт это давление: другое `--p-out` — другая точка.

Ключи сверяются с регистрацией `add…Option("KEY")` в `Common/src/CConfig.cpp` v8.6.0, если найден исходник
(`--su2-src` или `$SU2_HOME`); на шаблоне — неизвестных ключей нет (770 зарегистрированных, проверено здесь).

## Запуск

```bash
python run_case.py --case core130 --level coarse --plan smoke --np 4 --time-limit 1190 \
       --shroud slip --vaneless slip --record                 # дымовой прогон (раздел «Проверка»)
python run_case.py --plan plan_smoke_p075.json --shroud slip --vaneless slip --record \
       --restart-from runs/core130_coarse_smoke_slip/restart_s1_ramp60.dat --restart-state 0.6,145905 \
       --out runs/core130_coarse_smoke_slip_p075                # прогон Б раздела «Проверка»
python run_case.py --plan plan_cont_p075.json --shroud slip --vaneless slip --record \
       --restart-from runs/core130_coarse_smoke_slip_p075/restart_s3_point_p075.dat \
       --out runs/core130_coarse_cont_p075                      # прогон В: продолжение точки
python run_case.py --case core130 --plan smoke075 --shroud slip --vaneless slip --record   # А.s1 + Б одной командой (так не запускался)
python run_case.py --case core130 --plan smoke --dry          # только cfg + SU2_CFD -d по первой стадии
python run_case.py --parse runs/core130_coarse_smoke_slip     # заново разобрать готовый прогон
python run_case.py --case taurus60 --level medium --plan design --np 64 --time-limit 7000 --out "$GTU_OUT"
python -m pytest -q test_run_case.py                          # тесты без SU2
```

- Сетка: `../geom/out/<case>_<level>/passage_<case>_<level>.su2` и JSON рядом; если их нет, скрипт сам
  вызывает `python ../geom/impeller.py --case <case> --level <level> --no-step` (или `--geom-out` для своей папки).
  Проверяется наличие семи маркеров; ось вращения обязана быть z (рампа частоты SU2 меняет только
  z-компоненту, код `CConfig::SetRate`).
- План стадий (`--plan`): каждая стадия — отдельный запуск SU2 с рестартом от предыдущей
  (`RESTART_SOL`, `SOLUTION_FILENAME`); частота и давление на выходе рампой идут от значений конца
  прошлой стадии. `smoke`: 0 → 0,6 номинала (рампа частоты 80 итераций, давления — 160, до 0,95 оценки;
  всего 170), 0,6 → 1,0 (80/160, всего 200), затем 150 итераций второго порядка на рабочей точке — 520
  итераций. `smoke075` — те же стадии с давлением 0,75 оценки в s2 и s3 (прошёл проверку по частям: прогоны
  А.s1 и Б). `design` — то же для облака с 6000 итерациями второго порядка. Свой план — JSON-список стадий
  (`name, frac, pfrac, iter` обязательны; `ramp, pramp, muscl` — по желанию); `--iter-scale` — множитель
  итераций. План проверяется до запуска (`validate_plan`): длина рампы должна быть меньше `iter` — SU2 считает
  итерации 0..ITER−1 и ставит конечное значение рампы на итерации, равной её длине (`CFluidIteration::UpdateRamps`),
  иначе стадия кончится недоразогнанной, а следующая начнёт рампу от заданных значений, а не от достигнутых.
- Продолжение: `--restart-from <restart_*.dat>` копирует рестарт в папку прогона под коротким именем (SU2 v8.6.0
  с абсолютным путём ~105 знаков в `SOLUTION_FILENAME` падал: «*** buffer overflow detected ***»); первая стадия
  идёт без рамп, а с `--restart-state ДОЛЯ,ДАВЛЕНИЕ` — рампами от этих значений. При рестарте адаптивный CFL
  начинается заново с 5, невязки в первые десятки итераций растут.
- Прочие ключи: `--shroud`, `--vaneless`, `--p-out` (давление последней стадии, промежуточные — в той же
  пропорции к оценке), `--frac`, `--turb`, `--cfl`, `--set ИМЯ=значение` (поле шаблона), `--extra "KEY= VAL"`
  (строка SU2 вне шаблона), `--np`, `--mpi-args` (по умолчанию `--mca mpi_yield_when_idle 1`: на общей
  машине с чужой нагрузкой процессы MPI уступают ядро при ожидании; здесь это дало 2,2 с на итерацию против
  4–6 с без него при загрузке 7–9 на 4 ядрах, замер грубый), `--ramp-freq`, `--time-limit` (общий на все
  стадии; по истечении — SIGTERM процессам `SU2_CFD`, через 30 с SIGKILL всей группе), `--su2-bin`, `--su2-src`,
  `--mass-tol`, `--record`. SIGTERM, SIGINT, SIGHUP самому скрипту останавливают SU2 так же, стадия получает
  статус `terminated`, итог пишется.
- Останов SU2: SIGTERM идёт процессам `SU2_CFD`, а не `mpirun`. SU2 v8.6.0 на SIGTERM доводит итерацию,
  сводит флаг останова между рангами (`COutput::GetConvergence`), пишет рестарт и выходит. `mpirun` OpenMPI
  4.1.6, получив SIGTERM сам, добивает ранги SIGKILL через `odls_base_sigkill_timeout` = 1 с (`ompi_info`):
  при итерации дольше секунды рестарт не записывался (прогон В и проверка ниже). Так было до исправления 14.11.2026.
- Оценка давления на выходе, у которой нет дозвукового решения на r = 1,3 r2 (запирание), останавливает
  скрипт с сообщением; раньше в cfg попадало комплексное число.
- В `run_summary.json` папки прогона: версия SU2, вход (сетка, число узлов, маркеры, ω, оценка p_вых),
  все параметры шаблона, по стадиям — статус (`finished`, `timeout`, `diverged`, `error`, `terminated`), секунды,
  невязки (начало, максимум, конец, наклон на второй половине), расход вход/выход и дисбаланс, PR и КПД,
  периодичность из журнала («Matched N points», число «Bad match»); затем проверки дымового прогона
  (`smoke_checks`): все стадии `finished` и нет NaN; невязки падают — в последней стадии наклон rms[Rho] на
  второй половине не больше −0,1 порядка на 100 итераций (порог принят здесь) и конец ниже максимума стадии;
  дисбаланс расхода ≤ `--mass-tol` при прямом течении. Остановленный по лимиту или вручную прогон проверку не
  проходит, но его история разобрана (`statuses`, `iterations_in_run`).

### Как считаются степень сжатия и КПД

- Свой расчёт по последней строке истории: π = p0(outlet)/p0(inlet), τ = T0(outlet)/T0(inlet) — средние
  по расходу (`MARKER_ANALYZE_AVERAGE= MASSFLUX`); η = (π^((γ−1)/γ) − 1)/(τ − 1) для идеального газа с
  постоянным γ. Выход — r = 1,3 r2, то есть колесо с безлопаточным участком.
- Столбцы SU2 `PRTT` и `TotTotEff` (группа `TURBO_PERF`, осреднение `MIXEDOUT`) пишутся рядом
  (`PRTT_su2`, `TotTotEff_su2`). По коду SU2 (`CTurboOutput.cpp`, навык `su2-turbo`) изоэнтропическая
  энтальпия там — h(s1, p2) + V2²/2, поэтому два КПД не обязаны совпадать.
- Расход: нормаль границы в SU2 смотрит внутрь области — при прямом течении вход > 0, выход < 0;
  `mass_sign_ok = false` — обратное течение на выходе. Колесо целиком — расход канала × Z (9 для core130).
- Одномерная оценка (`d1.PR`, `d1.eta_comp_stage`, `d1.m`) пишется рядом для сравнения, не как эталон.

## Проверка

(средняя загрузка 5–15), поэтому 0,5–3,2 с на итерацию. Случай `core130`, уровень coarse.

   давления с обратной подстановкой в неразрывность и с запиранием, проверка плана, разбор истории и журнала,

   `mpirun` на подставном процессе, полный сухой проход `main` на сетке geom coarse: три cfg и цепочка рестартов).
2. Сухой прогон `--dry`: `SU2_CFD -d` по первой стадии — «Exit Success»; ключи шаблона — все среди 770
   зарегистрированных в `CConfig.cpp` v8.6.0.
3. Периодичность на сетке geom coarse: «Matched 6270 points with a max distance of: 1.70109e-16», «Bad match» нет.
4. Повторяемость: один и тот же cfg на 4 процессах дважды дал совпадающие истории (расход на входе на
   72-й итерации 0,129156504 кг/с в обоих); на 4 и на 2 процессах (сетка `--gap 0`) — расхождение в пятом знаке
   (0,147413 и 0,147422 кг/с на 101-й итерации): разбиение сетки меняет порядок суммирования.

### Почему расчёт расходился на разгоне (диагностика)

Пробные прогоны навыка `su2-turbo` (сборка без MPI) расходились на 40–78 % частоты, причина не была найдена.
Здесь — ASCII-рестарт каждые 2 итерации до NaN и поиск экстремумов поля (сводка с числами —
`su2_results.json`, ключ `diagnostics_2026_11_14`):

| сетка | покрышка | итог | поле за 1–2 итерации до NaN |
|---|---|---|---|
| geom coarse, зазор 0,30 мм (одна ячейка по высоте), 139 121 узел | неподвижна | NaN на 72-й итерации, 54 % частоты | T от 1,5 до 1202 К, M до 9,4 у выходной кромки в зазоре (r/r2 0,97–1,0, z 102,1–103,0 мм при плоскости покрышки 102,65 мм); T > 500 К в 1969 узлах вдоль вершины (r/r2 0,73–1,0) |
| та же геометрия с `--gap 0` (`impeller.py`, в `runs/`), 49 933 узла | неподвижна | NaN на 101-й итерации, 60 % | T от 9,7 до 1857 К, M до 4,2 на линии касания вершины лопатки и покрышки у выходной кромки; T > 500 К в 1306 узлах вдоль всей вершины (r/r2 0,63–1,03) |
| `--gap 0` | вращается, стенки за колесом неподвижны | NaN на 81-й итерации, 60 % | не записывалось; стык вращающейся и неподвижной стенок — на r2 |
| `--gap 0` | вращается вместе со стенками за колесом | без NaN 170 + 131 итерация, до 100 % | физически другое колесо: стенки вращаются до 1,3 r2, π по SU2 доходило до 28 — остановлен |

Вывод: расходится там, где неподвижная стенка примыкает к вращающейся через одну ячейку (зазор в одну ячейку,
линия касания, стык на r2): относительная скорость U ≈ 300 м/с падает до нуля на одной ячейке, температура там
уходит за физические пределы, затем NaN. Средние по входу и выходу при этом ничего не предвещают. Ещё два
наблюдения, учтённые в плане `smoke`: (а) рампа давления на выходе от p01 при неподвижном колесе даёт втекание
и со входа, и с выхода; (б) линейная рампа давления той же длины, что рампа частоты, в середине разгона выше,
чем колесо держит (давление нужно ~n²), — расход падал до 0,03 кг/с на канал при расчётных ≈ 1,1.

Для открытого колеса нужна сетка, где зазор разрешён несколькими ячейками (по README узла geom на medium их
две, на fine три; хватит ли — не проверено), с призматическим слоем у стенок; это работа узла geom. Пока для
дымового прогона покрышка и стенки за колесом заданы без трения (`--shroud slip --vaneless slip`): нет сдвига
на стыках, но нет и трения о покрышку и стенки безлопаточного участка — эта часть потерь не учтена.

## Узел по сетке и точке: `su2_case.py`

`run_case.py` строит постановку от случая узла geom (`--case`) и одномерной оценки `d1` из JSON сетки. `su2_case.py`
берёт **любую сетку канала** (`.su2` или `.su2.gz`) и **расчётную точку из results-JSON трека** (`файл.json:ключ`,
поля как у `stage1`/`stage2` в `routes/gtu/frame3/frame3_point_results.json`). Процессы SU2 (поиск `SU2_CFD`,
`mpirun`, лимит времени и мягкий останов с записью рестарта, разбор журнала, деление стенок за колесом) — функции
`run_case.py`, проверенные дымовыми прогонами выше; конфигурация, план стадий, разбор и сравнение — свои.

```bash
python3 su2_case.py run --geom-results ../../frame3/frame3_geom_results.json --stage stage1 --level coarse \
        --point ../../frame3/frame3_point_results.json:stage1 --points 0.75:3000 --np 4 --time-limit 2400 \
        --out <папка> --record <results.json>                     # пробный прогон (ниже)
python3 su2_case.py run --mesh passage.su2.gz --mesh-json impeller.json --point point.json:stage2 --dry
python3 su2_case.py run ... --speed 0.9 --points 0.55:3000,0.62:2000,0.68:2000   # линия частоты по противодавлению
python3 su2_case.py run ... --restart-from <папка>/restart_p1_0_750.dat --restart-state 1.0,253734 --points 1.0:2000
python3 su2_case.py parse <папка> [--record <results.json>]      # заново разобрать прогон
python3 su2_case.py aws-plan --trial-results su2_trial_results.json --out jobs_frame3.json   # AWS не вызывается
python3 -m pytest -q test_su2_case.py
```

- **Вход и сверка.** Сетка — из сводки узла геометрии (`--geom-results`, `--stage`, `--level`: пути и SHA-256 файлов
  сетки; SHA-256 сверяется, сжатая копия `.su2.gz` распаковывается в папку прогона) или прямо (`--mesh`, `--mesh-json`).
  До запуска сверяются точка и сетка (`consistency` в сводке): ω точки (n_rpm) и `su2.rotation_rate_rad_s` сетки,
  p01 и T01, число каналов 360/угол = Z точки, двусторонний вход у обеих, семь маркеров; расхождение — останов
  (`--force` — считать всё равно). У двустороннего колеса сетка — одна сторона, расход колеса = канал × Z × 2.
- **Конфигурация** (`build_config`, ключ — значение; имена сверяются с регистрацией в `Common/src/CConfig.cpp`
  v8.6.0, если найден исходник `--su2-src`/`$SU2_HOME`): `SOLVER= RANS`, SST (V2003m по умолчанию SU2), идеальный
  газ γ = 1,4, Сазерленд; `ROTATING_FRAME` с ω точки × доля частоты стадии; `MARKER_PERIODIC` (periodic_1,
  periodic_2, угол +360/Z по z); Giles: вход `TOTAL_CONDITIONS_PT` p01, T01 точки по нормали, выход
  `STATIC_PRESSURE_1D`; `MARKER_TURBOMACHINERY`, `AXIAL_CENTRIFUGAL`, `TURBO_PERF_KIND= COMPRESSOR`; стенки — как
  `run_case.py` (`--shroud`, `--vaneless`, по умолчанию `slip`/`slip` — вариант, прошедший дымовую проверку);
  численная схема — та же, что в дымовом прогоне Б (Roe, первый порядок на разгоне, MUSCL на точке, CFL 5 с адаптацией
  1–20, `MGLEVEL= 0`); средние по расходу `MARKER_ANALYZE_AVERAGE= MASSFLUX`. Числа схемы меняет `--set ИМЯ=значение`.
- **Давление на выходе** (`estimate_p_out`) — оценка по точке, граничное условие, а не результат: p02 = p01·(1 +
  η_эф·(T02/T01 − 1))^(γ/(γ−1)) с η_эф из PR и T02 точки (ступень, с диффузором — для колеса оценка занижена на
  потери диффузора), закрутка Cθ2 = c2·sin α2 точки, переносится на r_out = 1,3 r2 по сохранению момента, Cm — из
  неразрывности расхода стороны колеса; при доле частоты f работа ∝ f², расход и закрутка ∝ f. Для KV-3 ступени 1 —
  338,3 кПа при расчётной частоте. Точки задаются долями этой оценки (`--points ДОЛЯ:ИТЕРАЦИЙ,...`) или своим
  давлением (`--p-out-design`).
- **План стадий** (`make_plan`): s1 — разгон до 0,6 частоты линии (рампа частоты 80 итераций, давления до min(0,95;
  доля первой точки) оценки при этой частоте — 160, всего 170), s2 — до частоты линии и давления первой точки (80/160, 200), обе первым
  порядком; затем точки вторым порядком, каждая с решения предыдущей, давление новой точки — рампой
  `--point-pramp` (100) итераций. `--iter-scale` масштабирует разгон, `--restart-from` пропускает его.
- **Разбор** (`analyse_stage`, по `history_<стадия>.csv` каждой стадии): невязки (начало, максимум, конец, падение
  от максимума всего прогона), расход канала на входе и выходе со знаком (нормаль внутрь: вход > 0, выход < 0) и
  дисбаланс |ṁвх + ṁвых|/ṁвх, π = p0вых/p0вх и T0вых/T0вх по средним по расходу, η = (π^((γ−1)/γ) − 1)/(T0вых/T0вх − 1),
  рядом `PRTT` и `TotTotEff` SU2 (mixed-out, другое определение КПД — раздел «Как считаются»), приведённый расход,
  изменение π, η и расхода в окне последних 500 итераций стадии, время итерации (столбец `Time(sec)` = ITER_TIME:
  медиана и нижний дециль) и загрузка машины до и после стадии.
- **Сошлась ли точка** (критерии навыка `su2-turbo`, раздел 6; не из документации SU2): нет NaN, прямое течение,
  rms[Rho] ниже максимума прогона не меньше чем на 4 порядка, дисбаланс расхода ≤ 0,5 %, π и η за последние 500
  итераций стадии меняются меньше чем на 0,1 % (`--conv-orders`, `--mass-tol`, `--window`, `--stab-tol`). Стадия
  короче окна — устойчивость не оценивается, точка не считается сошедшейся.
- **Сравнение с точкой** (`vs_point` у каждой стадии и `final`): расход колеса, π, T0-отношение и η против точки —
  сравнение, не проверка (точка — одномерная модель ступени с диффузором, SU2 — колесо с безлопаточным участком).
- **Итог** — `case_summary.json` в папке прогона; `--record` дописывает краткий итог в results-JSON (поля `method`,
  `software` с версией SU2 и коммитом исходника, `date`, `inputs` с SHA-256 точки и сетки, `runs`).

## Ограничения и что не сделано

- Сетка узла geom — только тетраэдры, без пристенных призм, в зазоре одна ячейка (coarse). y⁺ не измерялся;
  при шаге у лопатки 3,3 мм (coarse) он заведомо далёк от 1, и SST без пристенных функций на такой сетке
  считает трение и отрыв неверно. Пристенные
  функции SU2 (`MARKER_WALL_FUNCTIONS`) на этой сетке дают «T_Wall < 0» и NaN при разгоне (навык `su2-turbo`,
  раздел 4). Для чисел характеристики нужна сетка с призматическим слоем (дело узла geom).
- Маркер `hub` в сетке geom один на втулку колеса и стенку безлопаточного участка (r2 < r ≤ 1,3 r2). `run_case.py
  --vaneless` делит hub и shroud на r2 в копии сетки, но неподвижные стенки за колесом на этих сетках дают
  расхождение на стыке (диагностика выше); в дымовом прогоне они без трения (`--vaneless slip`).
- Дымовой прогон — с покрышкой без трения: это не открытое колесо с зазором, а его упрощение; трение о
  покрышку и о стенки безлопаточного участка не учтено.
- Выход области — r = 1,3 r2: π и η — колеса с коротким безлопаточным участком, не ступени с диффузором.
- Давление на выходе — оценка по одномерной модели; одна точка, характеристика (линия частоты от запирания до
  границы устойчивости) не строилась. Граница устойчивости стационарного расчёта — не граница помпажа.
- Сверка с эталонами (Rotor 37, CC3, SRV2-O) не выполнялась: данных в контейнере нет (см. выше).
- Что нужно от узла geom, чтобы считать открытое колесо с неподвижной покрышкой: зазор над вершиной в
  несколько ячеек по высоте (сколько хватит — не проверено; на coarse одна — расходится), призматический слой
  у стенок, отдельные маркеры стенок безлопаточного участка (`hub_vaneless`, `shroud_vaneless`) и сгущение у
  стыка на r2.
- Сетки medium и fine и прогоны на AWS не запускались (здесь — запрет реальных вызовов AWS).
