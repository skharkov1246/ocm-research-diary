# Эскизы внешнего вида вариантов уровня 1 (оценка)

Решение владельца 14.11.2026: к каждому из 50 вариантов уровня 1 — эскизы внешнего вида с трёх ракурсов.
Эскиз строится по размерам уровня 1 (поле `geometry` каждого варианта, `funnel_l1.layout`) и **не является
конструкторской документацией** — эта подпись стоит на каждом листе.

## Файлы

| файл | что это |
|---|---|
| `funnel_sketch.py` | генератор: трёхмерная модель внешнего вида по `geometry`, три вида в одном масштабе, `sketch_dims.json` |
| `test_sketch.py` | тест: габарит модели против JSON (1 %), три картинки у каждого варианта, повтор, два входа и колесо между камерами, рекуператор (сбоку — на +y; в корпусе — буквы C и D видны, закрытые модули — скрытым контуром), число ядер, своя буква у каждой точки (E1/E2, G1/G2), фланец B не на оси вала при приводе с холодного конца, проверка `--px-per-m`, подпись масштаба аксонометрии, колёса на эскизе = `geometry.compressor`, рендер не зависит от числа процессов |
| `make_fixtures.py` | фикстуры теста: настоящие концепции уровня 0 через `funnel_l1.evaluate_point` → `funnel_l1.layout` для форм, которых нет в отладочном топ-50 |
| `fixtures_l1_layout.json` | 11 классов формы: рекуператор в корпусе и сбоку, кластер 2 и 4 ядра, выносная камера, волновой ротор, RDC, радиальная турбина + один вал + масло, осевые + центробежная, диагональная, двусторонний вход + один вал |
| `sketch_dims.json` | результат: габарит JSON, габарит модели, габарит по правилу компоновки, габарит узлов без обвязки, отклонения, масса (оценка), высота оси, условные и скрытые узлы, модули (и чем закрыт модуль), точки подключения, замечания к компоновке, колёса компрессора по нарисованному профилю (`compressor_wheels_drawn_m`: D1t, D2, корпус) и размеры каждого нарисованного узла (`drawn_nodes_m`), масштаб и его проверка (`scale_overflow`), пикс./м вдоль осей аксонометрии |
| `examples/` | три примера листов (не больше 200 КБ): вариант 1 — вид сбоку и аксонометрия, вариант 2 — аксонометрия |

Полноразмерные листы (PNG 2800×1750) в репозиторий не кладутся — папка `--out`.

## Что на листе

- **Три вида, один масштаб для всего набора** (наибольший целый десяток пикселей на метр, при котором входит любой вид
  любого варианта; какой вариант ограничил масштаб — `scale_limited_by` в `sketch_dims.json`): 1 — вид сбоку, ось вала
  горизонтально, ортогональная проекция (смотрим с −y, вход слева); 2 — вид с торца со стороны выходного вала,
  ортогональная проекция; 3 — аксонометрия 3/4, параллельная проекция (азимут 55°, возвышение 30°).
- **Размеры:** L, W (или H) — по габариту с обвязкой; h — высота оси выходного вала над рамой. Высоты оси пакета в данных
  нет (запрос заказчику, навык gtu-dropin), принято 0,5·H — как в `funnel_l1.layout`. Масштабная линейка 1 м на
  ортогональных видах, на аксонометрии — отрезки 1 м вдоль осей X, Y, Z. На аксонометрии масштаб набора действует в плоскости
  проекции, вдоль осей модели он меньше (при азимуте 55° и возвышении 30°: X — 0,87, Y — 0,71, Z — 0,87 от него; у 380 пикс./м —
  330, 268, 329) — это написано в штампе и легенде листа и записано в `axo_axis_px_per_m`.
- **Заданный масштаб проверяется:** `--px-per-m` больше наибольшего, при котором входят виды какого-либо варианта, — ошибка
  с перечнем вариантов и их наибольшим масштабом (`--allow-overflow` рисует всё равно и пишет об этом на листе и в
  `scale_overflow`).
- **Модули замены** — оттенками серого и номерами-выносками в порядке списка `modules` варианта (1 — ротор или картридж
  ротора, у кластера — ядро; дальше горячая часть, камера, силовая турбина, модуль рекуператора…). Модуль, места и размера
  которого в данных нет (контроллер магнитных подшипников), не рисуется — так и написано в легенде; блок датчиков и
  привод ВНА — условная коробка у своей точки подключения (в легенде — белый квадрат штрихом). Модуль целиком внутри
  барабана рекуператора снаружи не виден: на виде сбоку — скрытый контур пунктиром и выноска к нему, в легенде — «внутри».
  Узлы вне модулей замены (вход, переходный канал, выхлопной коллектор, вал) — светлая заливка без номера, строка в легенде.
- **Ступени компрессора** — в легенде: D1t → D2, корпус, x от и до (то, что нарисовано точками профиля корпуса).
- **Точки подключения** — буквами в рамке, у каждой точки своя буква: A — выходной вал, B — вход воздуха (B1, B2 —
  двусторонний вход; площадь в легенде — каждого фланца и всего), C — выхлоп, D — топливо, E — масло (E1, E2 — у передней и
  задней опоры; «2 линии» — подвод и слив у одной опоры), F1…F3 — электрика, G — отбор и перепуск воздуха (G1, G2, если есть
  и перепуск на подогрев входа; буква добавлена к списку владельца: в `geometry.connections` есть точка «воздух: пусковой
  перепуск / отбор»). Положение по оси — из компоновки, по окружности — условно. Точка под барабаном рекуператора (топливо,
  выхлоп) выводится на его поверхность или на открытую часть коллектора — условно, с пометкой в легенде.
- **Фланец входа B при одностороннем входе:** при выходном вале со стороны выхлопа — круг на торце коллектора; при приводе с
  холодного конца торец занят валом и муфтой, поэтому фланец — сверху коллектора (радиальный подвод, как у пакетов с
  приводом с холодного конца), место и форма условные. Если площадь фланца (25 м/с) больше, чем помещается на коллекторе
  (D = 1,6·D1t), это написано: переход с воздуховода на коллектор в данных не задан.
- **Линии:** сплошная — контур узла по расчётным размерам; **штрих — условно** (размера в данных нет: опоры, фланцы входа и
  выхлопа по форме, газоходы ядер кластера, барабан волнового ротора по диаметру, патрубки выносной камеры, воздуховоды
  рекуператора); пунктир — скрытые корпуса магнитных подшипников (вид сбоку); штрихпунктир с двумя точками — габарит с
  обвязкой; штрихпунктир — ось. Перечень условного у каждого варианта — в легенде листа и в `conditional_notes`.
- **Стиль** — ведомость на белой бумаге (навык tkp-vedomost): монохром, Liberation Serif (метрический аналог Times New
  Roman), без жирного и без цветных плашек; модуль различается и оттенком, и номером.

## Модель и проверки

Узлы — тела вращения и параллелепипеды по полям `geometry`, м: вход (коллектор D, L или две радиальные камеры W×H),
ступени компрессора (D1t → D2 → корпус D_case по длине ступени), камера (кольцевая и RDC — цилиндр D×L, волновой ротор —
камера и условный барабан, выносная — вертикальный цилиндр над корпусом на `z_center`), турбина (корпус горячей части),
переходный канал, силовая турбина (корпус 1,3·Dtip — правило `funnel_space` для габарита и стыков модуля, не расчёт
корпуса), выхлопной коллектор, вал и фланец муфты, рекуператор (кольцевой барабан D_outer×L или кубы модулей сбоку по
рядам), ядра кластера по схеме k×m. Профили между заданными диаметрами — прямые отрезки. Блок рекуператора сбоку стоит на
стороне +y — за двигателем на виде сбоку и в аксонометрии, чтобы не закрывать главный вид (сторона в данных не задана —
условно). У двустороннего входа колесо 1-й ступени с двумя входами показано условно штрихом между камерами (Ø по ступени 1,
ширина — зазор камер); ступень 1 по данным стоит за входом, это записано в замечания.

Габарит с обвязкой **собирается из размеров узлов** по правилу компоновки уровня 1 (корпус компрессора + 0,5 м; 1,3·Dtip
силовой турбины + 0,5 м; рекуператор в корпусе — по объёму; блок сбоку — столбцы × сторона + 0,3 м; выносная камера +1,2·D;
ядра кластера), а не копируется из `envelope`. Тест сверяет с JSON в пределах 1 %: габарит по правилу; габарит всей модели
(обвязка + выступающие узлы); длину — отдельно по цепочке узлов без обвязки. Узел, выходящий за габарит, не подрезается, а
пишется в `issues` варианта и в легенду листа.

Итог на отладочном топ-50 (KV-3, N = 2000, вариантов в файле — 2): оба варианта сходятся с JSON (наибольшее отклонение
0,004 %), масштаб 1 м = 380 пикс. Фикстуры: 9 из 11 сходятся, 2 с выносной камерой — нет (ниже); свой набор фикстур
идёт в масштабе 1 м = 210 пикс. (ограничивает `radial_1shaft_oil`, W = 7,40 м), в 380 пикс./м он не входит — генератор
это ловит. Выноски проверены рендером: у всех 13 вариантов (2 + 11) каждая буква и каждый нарисованный модуль видны хоть на
одном из трёх листов.

## Замечания к компоновке уровня 1 (найдены эскизом)

1. **Выносная камера выходит за габарит.** В `funnel_space.derive` у выносной камеры L = 3·D, в `funnel_l1.layout` ось камеры
   вертикальная, центр — на 0,5·D_case + 0,6·D над осью, а к H добавлено только 1,2·D. Верх камеры выше габарита (фикстура
   `comb_ext`, idx 8: на 0,69 м, H модели 2,89 м против 2,20 м; кластер `cluster2`, idx 99: на 0,39 м), низ камеры заходит в
   корпус. Объём габарита входит в балл размера, поэтому у вариантов с выносной камерой балл размера, по-видимому, завышен.
   Исправлять — в `funnel_l1.layout` (z_center = 0,5·D_case + 0,5·L + зазор; H += L + зазор) до слияния уровня 1 на AWS; эскиз
   при этом пересчитывать не нужно — он читает новые поля.
2. **Блок рекуператора сбоку расширяет двигатель без проверки ширины пакета.** Правило `envelope` проверяет только D_env, а
   блок кубов сбоку добавляет к W столбцы × сторону + 0,3 м: у фикстур W = 2,96 м (`recup_side`) и 7,40 м (`radial_1shaft_oil`,
   4 куба поперёк при одном ряде вдоль). Ширину пакета KV-3 в правило стоит добавить (`tgt["pkg_W"]`).
3. У кластера 2×2 с выносными камерами камера нижнего ядра входит в верхнее ядро: в выборочных фикстурах такой концепции
   не выпало, производный случай (ядра фикстуры `cluster4`, камера фикстуры `cluster2`) проверен тестом — эскиз пишет
   пересечение в `issues` (код `intersect`).
4. **Двусторонний вход: обе камеры перед колесом.** Тип входа — «радиальная камера с двух сторон колеса», а
   `funnel_l1.layout` ставит ступень 1 за входом (x0 = L входа), то есть обе камеры перед колесом. Эскиз рисует колесо между
   камерами условно и пишет замечание (код `double_inlet_order`). Двусторонний вход — у 164 из 256 концепций уровня 0
   (`funnel_l0.csv`, KV-3), в том числе у варианта № 2 отладочного топ-50. Длина двигателя с колесом между камерами в данных
   не посчитана.
5. **Рекуператор в корпусе длиннее участка между входом и выхлопом.** Длина барабана 0,8·L_core, положение по длине не задано;
   у фикстуры `recup_integral` (idx 213) барабан 1,715 м при участке 1,171 м, по центру он закрывает конец входа на 0,141 м,
   выхлопной коллектор на 0,403 м из 0,618 м и целиком модули 1–3 (код `recup_overlap`). Рекуператор в корпусе — у 24 из
   256 концепций уровня 0. Положение барабана по длине стоит добавить в `funnel_l1.layout`.

## Команда перерисовки итоговых 50 (после прогона уровня 1 на AWS)

Эскизы считаются локально: 150 листов — около 4 с процессорного времени на лист (2,5–3 мин на 4 ядрах); AWS не нужен.
Нужен Python с pyvista (VTK; без экрана — OSMesa или `vtk-osmesa`), matplotlib, pillow, numpy.

```bash
cd routes/gtu/funnel
# funnel_l1_top50.json и funnel_l1_results.json - итог merge_l1.py по частям AWS
python sketch/funnel_sketch.py --input funnel_l1_top50.json --results funnel_l1_results.json \
    --out "$GTU_OUT/sketch" --dims sketch/sketch_dims.json --workers "${NPROC:-4}" \
    --examples sketch/examples --example-sheets 1:side,1:axo,2:axo
python -m pytest -q sketch/test_sketch.py
```

`--px-per-m` фиксирует масштаб (например, чтобы листы KV-1 и KV-6 шли в масштабе KV-3; если у какого-то варианта виды
при нём не входят в поле — ошибка с перечнем, `--allow-overflow` — рисовать с пометкой на листе); `--only 3,17` — перерисовать
отдельные варианты; `--no-render` — только модель и `sketch_dims.json` (нужен лишь numpy). Фикстуры теста пересобираются
`python sketch/make_fixtures.py` (интерпретатор с cantera и scipy, как для `funnel_l1.py`).

Все размеры и массы — оценка уровня 1; точки и формы, которых нет в данных, помечены условными на каждом листе.
