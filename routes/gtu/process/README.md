# Сквозные концепции «топливо → вал»: пространство, оценка «КПД на тонну», MAP-Elites, задачи AWS

Узел трека «Простая литая ГТУ-заменитель» (`routes/gtu`, issue #59), папка `process`. **Статус: черновик, уровень облика
(15.11.2026).** Числа этого README — из `process_results.json` (пишет `process_results.py`) и `jobs_process.json` (пишет
`make_jobs_process.py`). Подпапки: `blocks/` — библиотека блоков (свой README), `mass/` — модель массы (свой README).

Фокус владельца 15.11.2026: «подбираем топовые конструкции всего процесса — от поступления топлива до вала; глубже в расчёты
не погружаемся; концентрируемся на геометрии, которая даст наибольшую эффективность и значительно повысит КПД на тонну».
Здесь — поиск таких конструкций: пространство сочетаний блоков и их облика, оценка каждой концепции и карта лучших по нишам.

## Критерий

Для типоразмера с фиксированной мощностью на валу (стык пакета: KV-3 — Taurus 60, KV-1 — Saturn 20, KV-6 — Titan 130,
генераторные исполнения):

- **КПД** на клеммах (цепочка блоков; сверка с frame3 −0,50 п. п. при калибровке трека ±2 п. п.);
- **масса** агрегата-заменителя: двигатель + камера + теплообменники + корпус и рама модуля (генератор, редуктор, вход и
  выхлоп пакета не входят) — модель `mass/`, калиброванная по 8 реальным двигателям (промышленная практика, LOO 22,8 %);
- **кВт/кг** и **«КПД на тонну»** = КПД % / масса т — цель MAP-Elites; в каждой нише ещё и **фронт Парето «КПД — масса»**;
- ограничения: допуск пакета (воздух и выхлоп до +20 %, выхлоп до +100 °C), правила совместимости блоков и воронки;
  Plug&Play «невозможно» — отказ; **детали и Plug&Play** — вторичные цели (отдельный отбор с ограничениями);
  **готовность** — наименьший TRL и множитель владельца 0,5 + 0,5·TRL/9 (отдельный отбор).

## Пространство (`process_space.py`)

| группа | гены и окна |
|---|---|
| топология цикла | рекуператор (ε 0,70–0,92; фольга / печать), промохлаждение воздух-воздух (место — после ступени k), повторный подогрев (x_rh 0,35–0,65; температура от T41 − 150 K до предела класса), IBC; топливо: нет / подогрев / паровой риформинг (S/C 1,5–3) / сухой (R 0,5–4) |
| камера | LPP (пассивный пилот, один клапан — решение владельца), FLOX, TVC, CAT, RDC, волновой ротор; кольцевая / выносная |
| компрессор | 1Ц, 2Ц, Д, ОЦ (1–3 осевые); вход одно- / двусторонний; Ti64 / Al / Ni; **π — по ln-диапазону типа** (`funnel_space.PI_RANGE`), **распределение π** (2Ц 0,35–0,65, ОЦ 0,12–0,60), коэффициенты работы ступеней (`MU_RANGE`), ширина b2 (cm2/U2 0,20–0,35) |
| турбина | осевая / радиальная, ступеней auto / 1 / 2 / 3; класс U / N / K / P / C (C — керамика Si3N4 / CMC); сплав — по способу; **T41 по классу**: от предела − 200 K (не ниже 850 °C) до предела `make_model.t41_limit`; ψ / U/C0, ca/U, силовая турбина |
| вал | прямой / свободная СТ / быстроходный через редуктор пакета |
| изготовление | **традиционная** (литьё в песок, кованые колёса), **литьё КНР** (точное литьё), **гибрид** (литые колёса и корпуса + печатная горячая часть и камера), **печать** (LPBF, оболочка возможна) |

Каждое значение гена осмысленно: непрерывный ген — доля окна, которое зависит от выбранных блоков. Бессмысленные по построению
сочетания заменяются ближайшими с записью в `repairs` (класс P при литой горячей части → N; оболочка без печатного корпуса →
картридж; промохлаждение при одной ступени сжатия → нет). Правила совместимости блоков не «чинятся» — их проверяет оценка.

**Ниши** (сетка 32 × 6 × 24 × 4 = 18 432): топология (Р, ПО, ПП, IBC, ХР — 2⁵), схема камеры, архитектура (компрессор ×
турбина × вал), изготовление. **Генератор по индексу**: концепция i точки KV — строка i последовательности Соболя (scramble,
сид 20261115·100 + номер точки, scipy 1.18.1); часть k из P — индексы [k·N/P, (k+1)·N/P).

## Оценка (`process_eval.py`)

1. Быстрый отказ по жёстким статическим правилам совместимости (0,2 мс).
2. `blocks.evaluate`: КПД, допуск пакета, геометрия и правила воронки, детали, Plug&Play, TRL.
3. Только у допустимых — масса: паспорт для `mass_model.size_from_passport` из результата блоков (расход, ступени и их π,
   частоты валов, выхлоп турбины, камера, подшипники, способ корпусов) + то, чего паспортный путь не видит (всё — оценка,
   основания в `process_results.json → evaluation.extra_mass_basis`): межтурбинная камера (блок камеры при давлении газа перед
   ней), колёса и улитки IBC, сердцевины теплообменников (поверхность `cycles.size_hx`; риформер и парогенератор —
   `cycles.hx_list`, пересчёт по расходу), катализатор (объёмная скорость 5000 1/ч), вентиляторы (6 кг/кВт), газоходы (лист,
   2 м, 30 м/с), плотность сплавов концепции вместо сплавов практики, волновой ротор (+ масса камеры). Оболочка не «снимает»
   корпус камеры: участок оболочки над камерой — тот же цилиндр.

**Сверка моста с моделью массы** (опорная точка frame3, `selfcheck.vs_mass_model_examples`): литьё в песок 6,42 т против
6,30 т примера модели массы (+1,9 %; расход цепочки блоков 26,8 кг/с против 25,55 у frame3), точное литьё КНР 4,20 т против
4,12 т (+1,9 %). Обратимость генома: все 22 опорные концепции блоков воспроизводятся по дискретным выборам (`roundtrip`).
Детерминизм: один остров при 1 и 3 процессах пула — один и тот же архив (`determinism`).

## MAP-Elites (`process_elites.py`)

Остров = машина: главный процесс ведёт архив, пакет концепций считается пулом на все ядра; порядок результатов пула фиксирован,
итог не зависит от числа процессов. Начало острова: опорные родители (примеры блоков + `process_seeds.json`), затем концепции
генератора по индексу [i·n_init, (i+1)·n_init) (30 % бюджета), дальше — потомки элит: гауссова мутация 0,40, iso+line 0,30,
сброс 1–2 генов 0,20, SBX 0,10 (операторы `evo/core/archive`). Родитель — из допустимых ниш (лучшая или точка фронта) с
вероятностью 0,8, иначе — турнир из трёх недопустимых ниш по сумме нарушений. Слияние: все острова, одна конфигурация
(отпечаток: версия, гены, окна, сетка, сиды, опорные родители), число оценок острова — заданное, без повторов; иначе отказ (код 2).

Что видно уже на мини-прогоне (наблюдения по элитам, `observations`; выборка мала — проверить на AWS):

   14 950 об/мин; `detail_top`). Но парно (та же ниша, другой вал)
   свободная СТ лучше прямого привода не всегда: медиана КПД на тонну ×1,03, хуже — в 41 % из 22 пар; быстроходный вал KV-3 —
   медиана ×0,96 (хуже в 5 из 8 пар), у KV-1 — ×1,09 (хуже в 2 из 8).
2. **Печать уменьшает детали в 3–4,5 раза** (медиана элит KV-3: 128 против 426–574 у остальных семей), а массу — не всегда: медиана массы элит
   печатной семьи 9,7 т против 8,3 т традиционной (в выборке больше теплообменников).
3. **Теплообменники окупаются по КПД, но не по КПД на тонну**: медиана простых элит KV-3 — 7,06 на тонну при 3,9 т, с
   рекуператором — 3,69 при 9,7 т; так же у KV-1 (15,2 против 10,0).
4. RDC и волновой ротор дают лучший КПД на тонну у KV-3, но при TRL 3; с множителем готовности впереди LPP и FLOX.

## Задачи AWS (`jobs_process.json`)

12 машин c7a.16xlarge (одна волна: us-east-1 384 vCPU + us-west-2 384 vCPU; us-east-2 — 5 vCPU, после одобрения заявки
получит машины без правки файла). Машина j считает остров j каждой точки: **KV-3 — 12 × 400 000 = 4,8 млн концепций, KV-1 и
KV-6 — по 1,2 млн**, всего 7,2 млн; число машин и оценок острова — флаги `make_jobs_process.py`. Смета: 31,8 ядро-часа (ЦП
мини-прогона × 1,5), около 3 мин счёта и 7 мин подготовки на машину, **ожидаемо 1,63 долл., верхняя граница 9,21 долл.**
(сторож 30 мин, MaxPrice 1,14 долл./ч). Это единицы долларов, а не десятки: концепция считается за ~10 мс. `runner.py plan`
(регионы us-east-1, us-east-2, us-west-2, квоты флагами) — **код 0**; путь «по требованию» (`--on-demand-fallback
--assume-no-spot`) — код 0.

```bash
python3 routes/gtu/platform/aws/runner.py run routes/gtu/process/jobs_process.json --branch claude/lucid-allen-yvps5d \
        --regions us-east-1,us-east-2,us-west-2            # DryRun; затем --live (сессия с ключами)
# после run: слияние каждой точки (команды - jobs_process.json -> merge.commands), в ветку - только process_aws_KV-*.json
```
Перед run код `process/` (включая `process_seeds.json`) должен быть в ветке `claude/lucid-allen-yvps5d`. Проверено в чистой
копии `git archive HEAD` с наложенными файлами узла: часть KV-3 и KV-6 считается и пишет файлы части.

## Допущения и что не сделано

- Всё — уровень облика: КПД узлов и пределы — модели воронки и блоков; масса — модель по 8 машинам с K промышленной практики;
  добавки массы (газоходы, вентиляторы, катализатор, рама, межтурбинная камера, IBC) не калиброваны.
- Межтурбинная камера считается по правилу основной камеры при давлении газа перед ней — в 2–3 раза тяжелее основной;
  последовательные камеры на горячем газе компактнее (уточнить).
- RDC и волновой ротор: выигрыш — модель перебора циклов (реализация 25 %, турбина −2 п. п.), TRL 3; масса камеры — как LPP.
- Выбросы показываются, но не отсеивают (ни один вариант уровня 0 камеры не выполняет все жёсткие цели).
- Остальные точки KV (KV-2, 4, 5, 7) — нет в воронке (`funnel_space.KV`); кластер ядер — нет в пространстве (модель массы —
  один газогенератор); радиальная турбина из двух колёс в массе — одно колесо на весь перепад (тяжелее).
- KV-6: опорные концепции воронки v3 в блоках недопустимы на краю (потери камеры по уровню 0 камеры 4,85 % против 4 % у
  воронки, AN²), допустимые найдены поиском — их мало; AWS покажет, есть ли простой цикл.
- Острова внутри эпохи не обмениваются; эпоха 2 — слитый архив как родители (`--parents`), по желанию.
- Живого прогона AWS не было; после коммита — пересобрать каталог (`node tools/build_catalog.mjs`, чистая копия HEAD,
  вторым коммитом).
