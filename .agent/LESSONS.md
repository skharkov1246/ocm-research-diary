# Уроки агентских сессий — разборы ошибок

Короткие правила — в `CLAUDE.md`, раздел «Уроки агентских сессий». Здесь — что
случилось, во что обошлось и как не повторить. Новый урок дописывается с датой.

## 14.11.2026 — трек gas-turbine (двигатель-заменитель, PR #60, #61)

1. **Каталог собирать из закоммиченного дерева.** Локально
   `node tools/build_catalog.mjs --check` проходил, а gate на PR #61 падал
   «каталог устарел». Сборщик обходит папки `routes/` и `calc/`, а не git: в
   рабочей копии лежали сгенерированные и игнорируемые файлы
   (`routes/gtu/platform/geom/out/*.json`), они попали в каталог, а в чистой
   копии CI их нет. Цена — красный gate и лишний круг. Правило: новые файлы
   коммитить первыми, каталог собирать в чистой рабочей копии HEAD и коммитить
   вторым коммитом:
   ```bash
   git worktree add --detach /tmp/wt HEAD
   (cd /tmp/wt && node tools/build_catalog.mjs && node tools/build_catalog.mjs --check)
   cp /tmp/wt/data/catalog.json data/catalog.json && git worktree remove --force /tmp/wt
   ```

2. **«Проверено» — только после зелёного gate.** Владельцу ушло «проверки
   репозитория пройдены» по локальному прогону; gate затем упал (п. 1).
   Правило: до зелёного gate писать «локально проходит, gate идёт».

3. **Сканер секретов в gate ловит буквальные строки.** Шаблон в
   `.github/workflows/gate.yml` срабатывает на `AKIA` и шестнадцать заглавных
   знаков и на имя поля секретного ключа AWS (в самом gate.yml оно записано как
   `aws_secret[_]access_key`, чтобы не находить себя). Код и тесты раннера AWS
   содержали такие строки — список имён для маскирования и фиктивные ключи в
   фикстурах; gate падал дважды. Правило: имена секретных полей и фиктивные
   ключи собирать из частей (`"aws_secret" "_access_key"`, `"AKIA" "FAKE…"`);
   перед push прогонять по изменённым файлам тот же шаблон, что в gate.yml.

4. **Скрипт, который тратит деньги, по умолчанию ничего не тратит.** Раннер
   `routes/gtu/platform/aws/runner.py` без флагов запускал реальные спотовые
   машины; я закоммитил его по требованию хука, до тестов. Правило: облачные
   запуски, заказы, рассылки — по умолчанию проверка или план; живое действие
   только явным флагом (`--live`) или переменной (`GTU_LIVE=1`). С опасным
   умолчанием или без тестов такой файл не коммитить.

5. **Значения секретов не читать.** Чтобы понять, настоящие ли ключи AWS в
   окружении, я пытался вывести их длину и начало; классификатор безопасности
   заблокировал. Правило: значения ключей и токенов не выводить даже частично;
   доступ проверять вызовом API (`aws sts get-caller-identity`) и наличием
   имён переменных.

6. **Требование хука закоммитить не отменяет проверок.** Фоновые агенты
   писали в репозиторий, и хук после каждого хода требовал коммита; я коммитил
   их работу почти без проверки. Правило: перед коммитом чужой или агентской
   работы — компиляция, тесты, сканер секретов, каталог из чистого дерева;
   незаконченное помечать в сообщении «черновик, тестов нет». Лучше: агенты
   пишут в scratchpad или свою папку, в репозиторий переносится проверенный
   итог.

7. **Имя модели — не в коммиты.** В трейлер `Co-Authored-By` я писал имя
   модели. Системное правило запрещает идентификаторы модели в коммитах, PR,
   коде и файлах репозитория. Правило: в трейлере — только ссылка на сессию.

8. **Предварительные числа — с пометкой и не в заголовок.** Паспорта линейки
   Solar и Siemens собраны по выдержкам поисковика (страницы производителей не
   открывались), а сводка «замена найдена у 32 из 34 исполнений» ушла
   владельцу как итог. Правило: число из выдержки поиска или из расчёта на
   непроверенных данных — «предварительно», с источником; в заголовок — только
   сверенное по первоисточнику.

9. **Изменение окружения — сначала одна строка владельцу.** Я расширил сетевой
   доступ окружения Default, не сказав в чате до вызова. Правило: перед
   изменением сети, переменных или секретов окружения — строка в чате, что
   меняю и зачем, затем вызов.

10. **Не молчать и не обрывать ход, пока идёт работа в фоне.** Владелец видел
    «остановку»: ход заканчивался, а в фоне шли сверка паспортов, агенты
    платформы и gate. Правило (просьба владельца 14.11.2026): по ходу работы —
    короткие строки «что делаю, что нашёл»; завершая ход при фоновой работе,
    перечислить, что идёт, чего ждём и что будет дальше.

11. **На вопрос «ты прочитал файлы из X?» — сразу «да» или «нет».** Сначала
    проверить подключённые инструменты и папку загрузок, затем ответить прямо
    и сказать, как дать доступ.

12. **Слияние — после зелёного gate и выполненного чеклиста PR.** Невыполненный
    пункт чеклиста либо выполнить, либо явно перенести с объяснением в PR.
