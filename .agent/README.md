# Старт за 60 секунд

Для того, кто открыл репозиторий впервые. Машинная версия — `.agent/manifest.json`.

## Что это

Открытый дневник квантово-химических расчётов MatterForge: десять продуктовых
треков, от окислительной конденсации метана до катодных материалов. Сайт
статический, рендерится на клиенте, собирается GitHub Pages **из ветки main** —
чего нет в main, того нет на сайте.

Живой сайт: https://skharkov1246.github.io/ocm-research-diary/

## Где что лежит

| Что | Файл |
|---|---|
| Дневник OCM (вкладка 0) | `entries.js`, массив `ENTRIES` → `index.html` |
| Дневник FeMoco и аммиака | `femoco_entries.js` → `femoco.html` |
| Все продуктовые вкладки | `assets/matterforge/matterforge_tabs_content.json` |
| Скрипты расчётов и результаты | `routes/`, `calc/` |
| Запуск на AWS | `payloads/`, `calc/aws_run*.sh` |
| Каталог всех данных | `data/catalog.json` |
| Известные пробелы провенанса | `data/known_gaps.json` |

## Что говорит каталог

`data/catalog.json` собирается сканированием (`node tools/build_catalog.mjs`)
и отвечает машинно: что посчитано, каким скриптом, попало ли в дневник.
На 04.09.2026: 322 набора данных, 151 файл результатов, из них 32 имеют
порождающий скрипт, 22 упомянуты на сайте, 3 несут метаданные расчёта.

Эти три числа — прямая мера воспроизводимости. Их рост и есть работа над
достоверностью.

## Проверки перед PR

```bash
node tools/validate.mjs             # схема записей, картинки, ссылки на расчёты
node tools/build_catalog.mjs --check # каталог актуален
node tools/smoke.mjs                 # три страницы рендерятся, ошибок консоли нет
```

Те же проверки выполняет `.github/workflows/gate.yml` на каждый PR и
`.github/workflows/pages.yml` перед публикацией: непрошедший контент на сайт
не попадёт, там останется предыдущая рабочая версия.

## Как добавить этап

1. Дописать объект в `ENTRIES` (`entries.js` или `femoco_entries.js`) либо запись
   в `updates` нужного таба в `matterforge_tabs_content.json`.
2. Обязательные поля записи: `id`, `date`, и двуязычные `stage`, `title`,
   `simple`, `tech`. Без `id` якорь записи станет `#undefined`.
3. Картинки — в `assets/…`. При правке `matterforge.js` или `matterforge.css`
   обновить штамп `?v=YYYYMMDD` в `index.html`.
4. Сослаться на файл результата в `routes/` или `calc/`. Если скрипта в
   репозитории нет — внести в `data/known_gaps.json`, а не умолчать.
5. Пересобрать каталог и прогнать проверки.
