# CalculiX: прочность, частоты и ресурс ротора

Узел платформы трека (issue #59): размеры колёс (`gtu_explore`, `gtu_dropin`, навыки `gtu-cycle`, `gtu-dropin`) →
геометрия (`platform/geom/impeller.py`) → CalculiX → запас по разрушению, частоты, ресурс. Состояние на 14.11.2026:
ccx 2.21 стоит в контейнере; `test_disk.py` (осесимметрия) — 12 из 12; самопроверка этого навыка
`scripts/ccx_selfcheck.py` — 7 из 7 (`scripts/ccx_selfcheck_results.json`, около 20 с на 4 ядрах). Трёхмерных
расчётов колёс трека ещё не было. Пометки: «(прогон)» — проверено запуском ccx 2.21 автором навыка; «(прогон
проверяющего)» — повторено или найдено при проверке навыка; «(док.)» — по исходнику руководства ccx
(`doc/CalculiX.tex`, ветка разработки), не запускалось; «не проверено» — как есть.

## 2. Установка и запуск

```bash
apt-get install -y -o DPkg::Lock::Timeout=300 calculix-ccx   # Ubuntu 24.04: 2.21-1 (noble/universe)
ccx -v                                                       # «This is Version 2.21»
OMP_NUM_THREADS=1 CCX_NPROC_EQUATION_SOLVER=1 ccx -i job     # читает job.inp; пишет job.dat, job.frd, job.sta
python3 .claude/skills/calculix-rotor/scripts/ccx_selfcheck.py --json /tmp/sc.json   # до любой работы
```

- Без ключа ожидания замок dpkg во время чужих установок роняет установку (`fea/README.md`).
- Пакет `calculix-ccx-doc` в noble — руководство версии 2.11 (старее программы); в этом контейнере файлы
  пакета в `/usr/share/doc` не распаковались (`path-exclude=/usr/share/doc/*` в настройках dpkg). Актуальное
  руководство и примеры — из репозитория автора, без выкачки всего дерева (2 с, 3 МБ; прогон проверяющего):
  `git clone -q --depth 1 --filter=blob:none --no-checkout https://github.com/Dhondtguido/CalculiX ccx && git -C ccx checkout HEAD -- doc/CalculiX.tex test/rotor.inp test/rotor.dat.ref`
  (сайт dhondt.de из сессии не открывается).
- Один поток на расчёт, параллельно — разные расчёты: однажды ccx 2.21 в 4 потока SPOOLES молча дал решение с
  невязкой равновесия 1,6 %; повторить не удалось — 24 прогона в 4 потока совпали с однопоточными
  (`fea/README.md`). Потоки — `OMP_NUM_THREADS`; `CCX_NPROC_STIFFNESS`, `CCX_NPROC_EQUATION_SOLVER`,
  `CCX_NPROC_RESULTS` важнее его (док.).
- Gmsh — `pip install gmsh` (4.15.2 в контейнере). Длительные расчёты — `timeout 1200`.

## 3. Порядок работы

**Шаг 0.** Самопроверка (выше): все `ok`, иначе стоп и разбор. Ворота качества `disk.py` не отключать.

**Шаг 1. Осесимметрия** — первый и дешёвый расчёт любого диска или колеса:
`cd routes/gtu/platform/fea && python3 test_disk.py && python3 disk.py case.json` (формат `case.json` — в README).
CAX8: ось вращения — y, радиус — x; ccx разворачивает элемент в C3D20 на секторе 2°; узлы на оси по радиусу
сам не закрепляет; сосредоточенные силы задаются на полную окружность (док.). В `disk.py` сосредоточенных сил
нет: нагрузка на ободе — давление `P2`. Лопатки учтены только массой, поэтому для лопаток и их корней нужен шаг 3.

**Шаг 2. Поле температур.** Пока OpenFOAM не дал поля — таблица T(r) в `case.json` (условно, помечать). Своё
тепловое решение ccx: `*HEAT TRANSFER, STEADY STATE` + `*BOUNDARY` по степени свободы 11 → `NT` в `.frd` →
в механическом расчёте `*TEMPERATURE, FILE=heat.frd, BSTEP=1` на той же сетке (прогон). Значения из файла
перекрывают заданные явно (док.). Перенос поля OpenFOAM на сетку ccx — не проверен.

**Шаг 3. Трёхмерный сектор колеса.** STEP из `impeller.py` → Gmsh/OCC: вырезать сектор 360/Z (основная лопатка +
полулопатка), `gmsh.model.mesh.setPeriodic(2, [грань_slave], [грань_master], T)` для узлов «в узел»; T —
16 чисел матрицы 4×4 по строкам, переводит master в slave (поворот на +360/Z, если slave впереди по углу),
`Mesh.ElementOrder = 2` → C3D10. Физическая группа — **только объём**; наборы узлов граней — из
`gmsh.model.mesh.getNodes(2, грань, includeBoundary=True)` и дописать `*NSET` в `.inp` (прогон, проверка `gmsh`).
- **Единицы STEP:** файл из `impeller.py` помечен как миллиметры (`SI_UNIT(.MILLI.,.METRE.)`), а числа в нём —
  метры. Gmsh читает их как есть (метры); для системы Н–мм–т–МПа — `gmsh.option.setNumber("Geometry.OCCScaling",
  1000)` до `importShapes` (прогон проверяющего). Сторонний CAD покажет колесо в 1000 раз меньше.
- **Наборы:** Gmsh пишет `*NODE` без набора и элементы в ELSET с именем физической группы (`EVOL`). Шаблон
  ниже ссылается на `NALL` и `EALL`, поэтому перед ним дописать `*NSET, NSET=NALL, GENERATE` / `1, <наибольший
  номер узла>` и `*ELSET, ELSET=EALL` / `EVOL`; без них ccx 2.21 останавливается на `*INITIAL CONDITIONS` и
  `*DLOAD` (прогон проверяющего; узлы Gmsh пронумерованы подряд с 1).

Шаблон — **частоты с преднагружением** при защемлённой ступице (N = 9 — колесо 9 + 9 полулопаток). Проверяющий
прогнал его дословно на секторе 40° кольца самопроверки (C3D20R и C3D10 из Gmsh): NLGEOM + CENTRIF + температуры
из `.frd` + ND 0–4, без ошибок (прогон проверяющего; автор — на том же кольце с N = 12).

```
*SURFACE, NAME=SSLAVE, TYPE=NODE
NSLAVE
*SURFACE, NAME=SMASTER, TYPE=NODE
NMASTER
*TIE, NAME=CYC, CYCLIC SYMMETRY
SSLAVE, SMASTER
*CYCLIC SYMMETRY MODEL, N=9, NGRAPH=1
0., 0., 0., 0., 0., 1.
*BOUNDARY
NHUB, 1, 3
*INITIAL CONDITIONS, TYPE=TEMPERATURE
NALL, 20.
*STEP, NLGEOM
*STATIC
*DLOAD
EALL, CENTRIF, 5.407e6, 0., 0., 0., 0., 0., 1.
*TEMPERATURE, FILE=heat.frd, BSTEP=1
*NODE FILE
U, NT
*EL FILE
S
*END STEP
*STEP, PERTURBATION
*FREQUENCY
12
*SELECT CYCLIC SYMMETRY MODES, NMIN=0, NMAX=4
*END STEP
```

- `CENTRIF`: ω² [рад²/с²], точка на оси, единичное направление оси (док.; ω² = 5,407·10⁶ — 22 205 об/мин,
  схема 130). Плотность обязательна. Вторая строка `*CYCLIC SYMMETRY MODEL` — две точки оси; `TIE=` нужен,
  только если циклических `*TIE` несколько (док.).
- `*TIE` — одна пара поверхностей; узлы slave нельзя закреплять другими SPC/MPC (док.), поэтому в `NHUB`
  узлов slave нет. Направление размножения сектора — от slave к master (док.).
- **Прочность — отдельным входом, не этим.** `NHUB, 1, 3` запрещает рост отверстия: на кольце самопроверки
  σθ у отверстия 66,6 МПа вместо 286,0 (прогон проверяющего). Статика для напряжений — тот же вход без второго
  шага, но с закреплением по правилу 3 раздела 5; так статика с циклическим `*TIE` совпала с аналитикой (прогон).

**Шаг 4. Частоты и диаграмма Кэмпбелла.** Для каждой частоты вращения сетки (минимум 0, середина, верхняя —
разгонная по норме заказчика) — отдельный вход: `*STATIC` с CENTRIF и NLGEOM, затем `*STEP, PERTURBATION` +
`*FREQUENCY`: жёсткость берёт напряжения, перемещения и температуру конца последнего непертурбационного
шага (док.). Без PERTURBATION частоты — ненагруженной конструкции. Частоты ccx — во вращающейся системе, без
Кориолиса (док.). Таблицы `.dat` разбирает `read_eigen` из `ccx_selfcheck.py`.
- В выводе `.dat` при циклике — отдельная таблица на каждый узловой диаметр, **каждая частота дважды**:
  `*FREQUENCY` с числом 12 даёт до 6 разных частот на ND (прогон); у кратных форм строк больше — на секторе
  N = 9 у ND 0 вышло 5 разных (прогон проверяющего).
- Семейство гармонического индекса h содержит формы с ND = N−h, N+h, …: сектор и полная модель 360° совпали
  только при сравнении множеств частот — 21 частота до 3,1 кГц, расхождение 0 (прогон, проверка `campbell`).
- **NMAX задавать явно = ⌊N/2⌋** (наибольший различимый ND: N/2 при чётном N, (N−1)/2 при нечётном, док.).
  Без NMAX ccx 2.21 считает только ND 0 (прогон проверяющего, N = 9 и 12: в исходнике
  `src/selectcyclicsymmetrymodess.f` умолчание NMAX = 0), хотя раздел `*SELECT CYCLIC SYMMETRY MODES` руководства
  пишет N/2 и (N+1)/2. NMIN > 0 без NMAX — `*ERROR … maximum nodal diameter` (прогон проверяющего). Модель с осью
  внутри (ступица без отверстия): ND 0 и 1 — отдельными шагами (док.).
- Между рассчитанными скоростями — Саутвелл f² = f0² + K(n/60)²: K по 0 и 6000 об/мин предсказал 12 000 об/мин
  с ошибкой 0,02–0,6 % (прогон). Пересечения — с прямыми f = EO·n/60.
- Опасно пересечение, где h = |EO − k·Z| для какого-то целого k (Z — число лопаток колеса; источники EO — число
  лопаток соседних венцов, стоек, горелок; EO 1–2 — дисбаланс). Правило — по выдержке поиска (Kushner:
  h = jN ± m); требуемая отстройка по частоте — из нормы заказчика, в сессии нормы не прочитаны.
- Кориолис: `*FREQUENCY, STORAGE=YES` в шаге с PERTURBATION, затем `*STEP, PERTURBATION` +
  `*COMPLEX FREQUENCY, CORIOLIS`, частот в нём не больше, чем в `*FREQUENCY` (док.); пример `test/rotor.inp` на
  2.21 совпал с эталоном, в `.dat` — направление F/B (прогон, повторено проверяющим). Отрицательное собственное
  число — мнимая частота: нагруженная жёсткость не положительно определена, конструкция теряет устойчивость
  (док.); в `rotor.inp` так выходят две первые формы (прогон).

**Шаг 5. Запас по разрушающей частоте вращения** — `disk.py`: средние окружные напряжения (Робинсон),
n_разр/n = sqrt(k·∫σв(T)dA / ∫σθ dA); k = 1 — верхняя оценка, настоящий k — из разгонных испытаний.

**Шаг 6. Ползучесть и Ларсон — Миллер.** Быстрая оценка — блок `lmp` в `materials.json` (только IN-713C):
P = T[K]·(20 + lg t[ч]), lg σ — полином от P (`disk.py`: по Мизесу в узле, по наибольшему главному, по Мизесу в
точках интегрирования, по σθ,ср сечения). Перераспределение — `*CREEP` (Norton: ε̇ = A·σⁿ·tᵐ, t — полное время,
все константы могут зависеть от T) в шаге `*VISCO, CETOL=…`:
- `CETOL` обязателен; нагрузка в `*VISCO` приложена сразу в начале шага, а не нарастает, как в `*STATIC` (док.);
  приращений по умолчанию 100 — для долгих сроков `*STEP, INC=…` (док.; в самопроверке `INC=10000`);
- в `*STATIC` ползучесть выключена: деформация ползучести 0 (прогон);
- модель ccx — перенапряжение: при `*PLASTIC` с пределом σт скорость A·(σ − σт)ⁿ, ниже σт ползучести нет
  (прогон: σт = 150 МПа при σ = 100 МПа — ноль). Без `*PLASTIC` предел нулевой (док.) — так для дисков без пластики;
- единицы для ползучести — Н, мм, т, с, МПа: в СИ (A = 10⁻⁴⁶ Па⁻⁵) ccx разошёлся на первом приращении (прогон,
  повторено проверяющим: «increment size smaller than minimum»);
- деформация ползучести в выводе — `PEEQ` (CEEQ ccx переводит в PEEQ, док.); проверка: 1,000·10⁻³ = A·σⁿ·t.

**Шаг 7. Малоцикловая усталость.** Цикл пуск — режим — останов: шаги `*STATIC` до режима (CENTRIF + T) и обратно,
`*PLASTIC, HARDENING=KINEMATIC` (кривая — истинное напряжение Мизеса от логарифмической пластической
деформации, док.), повторять до стабилизации петли; размах деформации в горячей точке → ε_a = σf'/E·(2N)^b +
εf'·(2N)^c (Мэнсон — Коффин — Баскин). Констант усталости в `materials.json` нет — ресурс в циклах не выдавать,
писать «нет данных». Кинематику — **только с NLGEOM** (без него ccx берёт линейную теорию пластичности, док.):
±1 % дал 308,53 МПа против 308,53 по Прагеру; без NLGEOM — 298,16 МПа, ниже предела текучести 300, −3,4 %
(прогон, проверка `lcf`). NLGEOM, заданный один раз, действует во всех следующих статических шагах (док.).

**Шаг 8.** Итог — в results-JSON рядом со скриптом расчёта (версия ccx, сетка, ворота, источники свойств).

## 4. Материалы с зависимостью от температуры

`*ELASTIC` — строки «E, ν, T»; `*EXPANSION, ZERO=T_ref` — средний КТР от T_ref (ε = α(T)(T−T_ref) − α(T0)(T0−T_ref));
`*PLASTIC` — наборы «σ, εp, T»; `*CREEP` — «A, n, m, T»; данные `*PLASTIC` и `*CREEP` интерполируются в точки T из
`*ELASTIC` (док.). Нужна `*INITIAL CONDITIONS, TYPE=TEMPERATURE`. Свойства `materials.json` сняты с выдержек поиска
(статусы в файле) — числа ресурса и запаса по ним «предварительно». Литое толстое сечение, вероятно, слабее
отдельно отлитых образцов (`fea/README.md`).

## 5. Обязательные правила

1. Перед расчётом колеса трека — зелёная самопроверка и `test_disk.py`; после — сходимость по двум сеткам.
2. Каждое число — из results-JSON расчёта; условный профиль или поле температур помечать «условно».
3. Закрепления сектора. **Статика (напряжения):** отверстие свободно; осевое — один узел (или кольцо в средней
   плоскости); поворот как жёсткого тела — окружная степень узлов master (DOF 2, если грань master лежит в
   плоскости x–z, как в самопроверке); ничего на узлах slave. Окружное по всей грани master точно только для
   кольца без лопаток; для колеса с лопатками достаточно одного узла — не проверено прогоном. **Частоты:** опора
   по посадке на вал (в шаблоне — `NHUB, 1, 3`), без узлов slave.
4. Единицы одной системы во всём входе; частоты ccx — «cycles/time» в единицах времени входа.
5. Ресурс без констант материала не выдавать; k в критерии разрушения не завышать (k ≤ 1).
6. В репозиторий — только скрипты, входы и итоги; `.frd` (десятки МБ) — в `runs/`, `out/` (в `.gitignore`).
7. AWS для осесимметрии и сектора не нужен (секунды–минуты). Облако — только через `runner.py`
   (DryRun по умолчанию, `--live` явно, пакет `calculix-ccx` в `apt` задачи); живой прогон ccx на AWS не проверен.

## 6. Типовые ошибки

- **Gmsh пишет в `.inp` элементы CPS6 физических поверхностей** (прогон, Gmsh 4.15.2), а без физических групп —
  все элементы, ещё и T3D3 (прогон проверяющего): ccx примет их как часть модели. Лечится правилом шага 3.
- **Шаблон шага 3 на сетке Gmsh без `NALL`/`EALL`** — ошибка чтения `*INITIAL CONDITIONS` и `*DLOAD` (шаг 3).
- **STEP из `impeller.py` в чужом CAD или с переводом единиц** — колесо в 1000 раз меньше (шаг 3).
- **Напряжения из входа с защемлённой ступицей** — σθ у отверстия занижено в 4,3 раза (шаг 3).
- **`*SELECT CYCLIC SYMMETRY MODES` без NMAX** — посчитан только ND 0 (шаг 4).
- **Напряжение у отверстия по грубой сетке:** 16 элементов C3D20R по радиусу — −0,53 %, 32 — −0,06 % (прогон,
  повторено проверяющим).
- **Сравнение частот сектора и полной модели по порядку** — ложное расхождение 22 % (прогон): сравнивать множества.
- **Ползучесть в `*STATIC`**, предел текучести в материале ползучести, СИ с A ≈ 10⁻⁴⁶ — см. шаг 6.
- **Кинематическое упрочнение без NLGEOM** — шаг 7.
- **SPOOLES в несколько потоков** без ворот равновесия — см. раздел 2.
- Узел slave без пары: ccx пишет ошибку и `jobname_WarnNodeMissCyclicSymmetry_<tie>.nam` (док.); угол сектора
  сверяется с NPHYS (по умолчанию N), допуск 0,01 рад; `CHECK=NO` нужен для дробных ND, когда N больше числа
  секторов (док.).

## 7. Проверка результата

1. Журнал ccx без `*ERROR`; `ccx_selfcheck.py` — `all_ok: true`.
2. Равновесие полудиска (`disk.py`, ворота 1·10⁻³ и 5·10⁻³) или реакции опор против ω²∫ρr²dV.
3. Аналитика самопроверки (сталь, кольцо 0,05–0,20 м, толщина 4 мм, 10 000 об/мин): σθ у отверстия 285,8 против
   286,0 МПа (C3D20R) и 286,00 (C3D10 из Gmsh); нагрев T(r) = ΔT·((r−a)/(b−a))², ΔT = 200 К: 218,3 против
   218,4 МПа; T(r) из `*HEAT TRANSFER` — до 6·10⁻⁴ К от логарифмического профиля.
4. Частоты: низшая частота каждого ND растёт с частотой вращения (так в самопроверке); сектор = полная модель
   хотя бы на одной скорости.
5. Две сетки: изменение максимума Мизеса, σθ,ср, частот и ресурса записано.
