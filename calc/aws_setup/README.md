# Giving the sandbox agent scoped AWS access (для α-O прогона)

Цель: дать этой Claude Code веб-сессии **минимально-привилегированный** доступ к AWS,
чтобы агент сам поднял большой EC2-инстанс, прогнал α-O CASSCF+NEVPT2 на реальной
геометрии CHA, забрал результат из S3 и **гарантированно погасил** инстанс.

Факты окружения (проверено): сеть до AWS **уже открыта** (Trusted пускает cloud SDKs),
`boto3`+`awscli` стоят. Не хватает только **кредов**. Секрет-стора в Claude Code web
пока нет → креды идут как **переменные окружения** в конфиге окружения (доки прямо
предупреждают: они видны всем, кто может редактировать окружение).

## Шаги

1. **На своей машине, с админ-доступом к AWS**, запусти:
   ```bash
   REGION=us-east-1 ./calc/aws_setup/setup.sh
   ```
   Он создаст: приватный зашифрованный S3-бакет, EC2 instance-role+profile (только
   `s3:PutObject` в один префикс), scoped IAM-юзера с проверенной политикой, и
   напечатает access key + готовый блок переменных окружения.

2. **Вставь напечатанные переменные** в конфиг окружения Claude Code
   (иконка облака → текущее окружение → шестерёнка → **Environment variables**,
   формат `.env`, без кавычек): `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
   `AWS_DEFAULT_REGION`, `ALPHA_O_S3`, `ALPHA_O_INSTANCE_PROFILE`, `ALPHA_O_TAG`.
   Сеть оставь **Trusted**. **Ключи в чат не вставляй** — только в конфиг.

3. **Перезапусти сессию** (переменные подхватываются при старте). Скажи мне «готово» —
   я проверю `aws sts get-caller-identity` и запущу прогон через leak-proof оркестратор.

## Безопасность (обязательно)
- Отдельный IAM-юзер, **никаких root/admin ключей**. Ещё лучше — временные STS-креды
  (`aws sts get-session-token`, короткий TTL) вместо долгоживущих.
- **Удали ключ сразу после прогона:** `aws iam delete-access-key --user-name alpha-o-agent --access-key-id <id>`.
- Поставь **budget-алерт** (команда в конце `setup.sh`).
- Политика ограничена регионом, тегом (гасить можно только свои инстансы), одним
  бакетом/префиксом, и `PassRole` только на EC2. Файлы политик: `user_policy.json`,
  `instance_role_policy.json` (проверены состязательно).

## Почему не `aws_run.sh`
Тот скрипт — in-instance обёртка, и его «dead-man switch» **дырявый** (fallback делает
`stop`, а не `terminate` → инстанс копится; не ловит SIGHUP при обрыве SSH). Реальный
запуск пойдёт через **оркестратор из песочницы**: launch с
`InstanceInitiatedShutdownBehavior=terminate`, IMDSv2, независимый watchdog, который
гасит инстанс по тегу по таймеру — утечка невозможна. (Строю его отдельно.)
